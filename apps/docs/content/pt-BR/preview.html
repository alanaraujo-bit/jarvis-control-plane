O ciclo é pedir → modificar → rodar → ver → inspecionar → consertar. Todo passo menos o ver já morava neste produto: um agente edita arquivos, sobe um servidor num terminal de verdade, e o diff está na Revisão. A Prévia é o passo que faltava.

Nada para configurar, nenhuma porta para adivinhar

De onde vem o endereço

A URL do servidor de desenvolvimento é lida da saída da própria sessão. Quando um agente roda npm run dev, o endereço que ele imprimiu já está no log que este produto guarda. Não existe configuração de porta, nem chute, nem varredura.

Essa é também a única coisa que um navegador não pode saber: qual sessão subiu este servidor. A Prévia acompanha a sessão ativa, então alternar entre dois agentes rodando dois servidores te mostra o certo sem perguntar.

Se uma sessão estiver servindo mais de uma coisa, a escolha é oferecida em vez de uma ser escolhida por você.

A detecção é automática; abrir é um clique

Nada abre sozinho. O endereço é detectado assim que é impresso, e a Prévia espera por você. Um agente reiniciando um servidor de desenvolvimento não deveria fazer uma janela aparecer por cima do que você estava lendo.

Só loopback, e isso é uma fronteira de segurança

A Prévia renderiza dentro da nossa própria janela. Se ela apontasse para qualquer host só porque uma string apareceu na saída do terminal, então qualquer programa que uma sessão rodar poderia escolher o que este produto exibe.

Então o endereço tem que ser loopback, e isso é aplicado no comando que abre — não só no scanner que encontrou. Os dois usam a mesma checagem, e ela analisa a URL direito, com uma biblioteca de URL em vez de casar um prefixo.

✓ permitido  http://localhost:4173
✓ permitido  http://127.0.0.1:5173

✗ recusado   http://127.0.0.1.evil.com
✗ recusado   http://localhost.evil.com
              os dois passam batido numa checagem de prefixo
✗ recusado   http://192.168.1.40:4173
              um endereço de LAN não é loopback, mesmo sendo seu

Uma janela separada, não um iframe

O iframe era a primeira escolha óbvia e não funciona. A política de segurança de conteúdo do aplicativo é default-src 'self'. Alargar ela colocaria a página de um servidor de desenvolvimento num contexto adjacente à superfície que consegue invocar todo comando deste produto — uma escalação de privilégio real trocada por uma conveniência de layout.

Um webview separado tem o próprio conjunto de capacidades, vazio. Então a Prévia abre ao lado do app em vez de dentro dele.

Recarregar

O botão isso mudou alguma coisa mesmo?, para um servidor de desenvolvimento sem hot reload. Ele existe porque a alternativa é sair do app, e sair do app é onde o contexto da sessão se perde.

Verificado de ponta a ponta contra um servidor real

O npx serve imprimiu um endereço Local e um de rede. A Prévia ofereceu localhost:4173 e excluiu silenciosamente o endereço de LAN. Abrir renderizou a página real na janela própria dela; o arquivo foi então editado em disco e Recarregar mostrou a mudança — o ciclo inteiro, fechado. Os dois temas, os dois idiomas, mais o estado vazio e o comportamento de acompanhar a sessão ativa.
