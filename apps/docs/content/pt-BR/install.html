O que você precisa

Windows 11
Ou Windows 10 com WebView2, que está presente em qualquer máquina atualizada nos últimos anos. Windows é a única plataforma que existe hoje.
Uma CLI de agente que você já usa
Claude Code (claude) ou Codex (codex), no seu PATH, já logada. O J.A.R.V.I.S. não instala elas e não substitui o login delas.
Git
O binário git. Detecção de projeto, Revisão, worktrees e histórico de commits todos perguntam ao Git em vez de reimplementá-lo.

Node e pnpm são detectados e informados se estiverem presentes, mas não são necessários para rodar o app — só para compilá-lo a partir do código.

Rodando o instalador

  1. Execute o instalador O modo de instalação é por usuário. Não há pedido de administrador, e nada é escrito fora do seu próprio perfil.
  2. O Windows vai te avisar sobre um publicador desconhecido Isso é esperado e é honesto. Os binários ainda não são assinados com um certificado Authenticode — veja abaixo. Escolha Mais informações → Executar assim mesmo se você confia na origem do instalador.
  3. Escolha um idioma O instalador detecta o idioma do sistema e oferece inglês e português (Brasil), batendo com os idiomas do próprio aplicativo.
  4. Abra A janela espera a checagem de primeira execução antes de aparecer, então você nunca vê a tela errada passando piscando. Uma primeira instalação mostra uma tela de boas-vindas uma vez; depois disso ela abre direto na Central de Missões.

A pegada de instalação é de 7,3 MB, medida no instalador real e não estimada. O Monaco responde por 1,04 MB disso e é carregado sob demanda, não na inicialização.

O aviso do SmartScreen, explicado direito

Duas questões de assinatura diferentes são confundidas o tempo todo, então aqui estão elas separadas:

O certificado Authenticode impede o Windows de avisar sobre um publicador desconhecido. Ele exige uma compra, não foi comprado, e isso é um bloqueio rastreado. Nada técnico está faltando — o pipeline de build já tem o formato para isso.

O par de chaves minisign prova que uma atualização veio mesmo de nós. Ele existe, funciona hoje, e toda atualização baixada é verificada contra uma chave pública compilada dentro do binário antes de qualquer coisa ser instalada. Uma atualização que falha na verificação é recusada em vez de aplicada.

Ou seja: atualizações são verificadas criptograficamente mesmo com o instalador sem assinatura. São garantias genuinamente diferentes.

Primeira execução

A tela de boas-vindas reaproveita a mesma varredura de ambiente que o produto usa em todo lugar e o mesmo seletor de pasta — não existe um fluxo de onboarding próprio que possa dessincronizar da coisa real. Abrir uma pasta por ali te deixa dentro da área de trabalho daquele projeto.

Ela é controlada por uma flag guardada e mostrada uma vez por instalação. Se essa checagem falhar, o padrão é já vista: uma checagem quebrada não pode conseguir deixar a janela escondida.

Confira a varredura de ambiente

Configurações → Ambiente lista o que foi encontrado: Git, Node, pnpm, Claude Code, Codex, GitHub CLI, com versões. Um provedor que não está no seu PATH não é oferecido quando você inicia uma sessão, e esta é a página onde você descobre por quê.

Atualizando

O atualizador consulta um endpoint, baixa em segundo plano, e verifica o download contra a chave pública compilada antes de instalar. Seus dados ficam intocados por isso: eles moram em %APPDATA%\dev.jarvis.desktop, inteiramente fora do diretório de instalação.

As checagens de atualização falham hoje, honestamente

O endpoint de atualização aponta para um local de release que ainda não foi publicado, então Verificar atualizações informa uma falha em vez de fingir estar em dia. Isso é um bloqueio rastreado sobre onde publicar, não um bug no atualizador.

Desinstalando

A desinstalação remove o programa e preserva seus dados — projetos, sessões, histórico, missões e configurações ficam todos. Reinstalar retoma exatamente de onde você parou. Se você realmente quiser tudo fora, apague %APPDATA%\dev.jarvis.desktop você mesmo; veja Onde ficam os seus dados.

Compilando a partir do código

Node 22+, pnpm, e uma toolchain Rust com as ferramentas de build MSVC.

pnpm install
pnpm dev          # roda o app de desktop contra o Vite
pnpm tauri build  # produz o instalador do Windows

Os testes em Rust, incluindo os que dirigem um PTY real e um repositório Git real:

cd apps/desktop/src-tauri
cargo test
cargo test -- --ignored   # também analisa toda transcrição do Claude Code desta máquina
Feche o app instalado primeiro

O produto força uma única instância para que exatamente um processo seja dono do banco e dos logs de sessão. Se a cópia instalada estiver rodando, o pnpm dev vai ser engolido em silêncio em vez de abrir uma segunda janela.

Depois: seus dez primeiros minutos Abrir uma pasta, rodar um agente, e escrever uma missão que ele tem que provar que terminou. Onde ficam os seus dados Todo caminho em que o produto escreve, e o que sobrevive a uma atualização.
