Você teve uma sessão longa com um agente semana passada. Ele sabia coisas — o formato do problema, o que você já tinha descartado, o arquivo que acabou importando. Aí você fechou a aba.

Ela continua lá.

  1. Encontre

    Dois jeitos, e eles servem memórias diferentes:

    • Histórico se você lembra mais ou menos quando. As sessões são agrupadas por dia e filtráveis por período, provedor e projeto. O Claude Code nomeia as próprias sessões, então muitas têm título de verdade.
    • Busca global (CtrlShiftF) se você lembra uma frase. Ela busca o que foi de fato dito dentro de toda sessão que você já rodou, e mostra a linha em que casou.
  2. Leia antes

    Uma linha abre uma prévia: a conversa, somente leitura. Turnos, chamadas de ferramenta, contagens de token. Nada é iniciado e nada é conectado — isto é uma projeção do log, e o log nunca foi a lugar nenhum.

    Leia o suficiente para lembrar onde você estava. Normalmente esse é o objetivo inteiro de voltar.

  3. Continue

    A prévia oferece o caminho de volta para um terminal:

    • Se a sessão ainda está viva, você reentra nela.
    • Se ela terminou, um agente novo é iniciado e recebe a conversa antiga, numa aba com o nome dela.
Verificado plantando um fato

Um fato foi plantado numa sessão, a sessão foi fechada, depois continuada, depois perguntada sobre o fato. A resposta voltou: "Âmbar."

Quando a oferta não está lá

As duas CLIs retomam por mecanismos opostos, e só uma delas pode ser acompanhada depois. Então o modelo de capacidades declara qual, e onde continuar não pode funcionar, a oferta está ausente com um motivo em vez de presente e silenciosamente quebrada.

Claude Code Fork — --resume <id> --fork-session honra o nosso próprio id de sessão e escreve uma transcrição nova com esse nome. A continuação é uma sessão que conseguimos acompanhar desde o começo.
Codex AppendInPlace — o codex resume anexa ao rollout que ele recebeu em vez de criar um. Um formato diferente, e a interface diz isso em vez de fingir que são iguais.
Se a pasta do projeto foi movida

Continuar dentro de uma pasta que não existe mais é recusado. Isso foi descoberto fazendo exatamente isso e vendo um agente real abrir no diretório pessoal do usuário — o que é pior do que um erro, porque aí o agente trabalha com confiança nos arquivos errados. A recusa cobre todo lançamento dentro de um projeto movido, não só esse caminho.

Continuar depois de uma troca de conta

Uma retomada não atravessa diretórios de configuração, então uma sessão que mudou de conta não pode ser retomada com --resume de jeito nenhum. A continuidade é carregada pelo briefing da Memória: a sessão nova começa sabendo o que o projeto sabe, que é a parte que de fato importava.

Apagar em vez disso

Se o que você quer é que ela suma: o Histórico apaga linhas, entradas do índice de texto completo e o diretório de log, e te diz quantos bytes liberou. Uma sessão viva é recusada em vez de meio apagada.

Não existe política de retenção, deliberadamente. A superfície diz quanto os logs custam para que apagar seja uma decisão que você consegue tomar, em vez de uma tomada em seu nome sobre o seu próprio histórico.
