Um projeto é uma pasta real no seu disco. Abrir um não copia, não indexa e não escreve nada dentro dela — o J.A.R.V.I.S. pergunta ao Git o que ela é e lembra onde ela está.

A área de trabalho: sete áreas sobre uma pasta

Sessões Terminais e agentes. A superfície principal, e onde o trabalho acontece. Arquivos A árvore, com entradas ignoradas pelo Git esmaecidas, e o Monaco atrás dela. Revisão O que mudou, atribuído à sessão que mudou. Prévia O servidor de desenvolvimento que um agente acabou de subir, aberto pelo endereço que ele imprimiu. Worktrees Dê a um agente o próprio checkout. Uma worktree é um projeto. Memória O que todo agente que começa aqui ouve antes de ler um arquivo. Configurações As regras de autonomia e proteção deste projeto.

Por que estas não ficam na barra lateral

Arquivos, o editor, Revisão, Prévia e Worktrees são ferramentas de escopo de projeto. Colocar elas na barra faria a barra ou crescer toda vez que uma for entregue, ou ter que responder "qual projeto?" a cada clique.

Então a barra fica com seis destinos e Configurações, e o cabeçalho do projeto carrega o resto. É uma regra mais sobre legibilidade do que sobre hierarquia: uma superfície de navegação que você não consegue absorver de relance deixou de ser navegação.

O confinamento de caminho é a fronteira de segurança

Como o acesso a arquivos é restringido

O webview só nomeia caminhos relativos à raiz do projeto, e a própria raiz é lida do banco de dados em vez de aceita de quem chamou. Duas checagens independentes vêm depois: a requisição não pode conter componentes .., de raiz ou de unidade, e então o caminho resolvido é reconferido contra o sistema de arquivos — para que um symlink apontando para fora do projeto seja pego mesmo com a requisição parecendo inocente.

Testado contra um diretório temporário real, incluindo caminhos verbatim do Windows (\\?\) e dobra de maiúsculas, porque são exatamente esses os lugares onde uma checagem ingênua de prefixo deixa passar algo que não deveria.

Recentes, e arquivar

Projetos que você abriu ficam na lista com caminho e branch. Arquivar um tira ele do caminho sem apagar nada — as sessões, missões e histórico que pertencem a ele continuam lá, e tudo que aponta para ele continua resolvendo.

Uma worktree é um projeto

Abrir uma worktree abre ela como projeto, em todo lugar. A Revisão dentro de uma worktree compara contra o branch daquela worktree, os Arquivos navegam aquele checkout, e a Memória é a que pertence a ela. Não existe código específico de worktree em lugar nenhum das superfícies de arquivo, editor, Revisão ou Git — que é o teste de se aquela decisão tinha o formato certo.

Um bug que se escondeu nesta estrutura

Toda área de projeto estava mostrando dados velhos. As áreas são montadas uma vez e escondidas com CSS, então um efeito chaveado no id do projeto nunca dispara de novo depois do primeiro projeto. O comentário da própria Revisão alegava que ela relia a cada visita; ela não relia. Vale saber se você estiver lendo este código: montado-e-escondido não é desmontado.

Uma sessão começa onde ela diz que começa

Se a pasta de um projeto foi movida ou apagada, iniciar uma sessão nele é recusado. Isso foi descoberto continuando uma sessão dentro de uma pasta apagada e vendo um agente real abrir no diretório pessoal do usuário — o que é pior do que um erro, porque aí o agente trabalha alegremente nos arquivos errados.
