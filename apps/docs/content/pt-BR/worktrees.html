Uma worktree do Git é um segundo checkout do mesmo repositório, no próprio branch, na própria pasta. É o jeito mais limpo de deixar um agente trabalhar em alguma coisa sem encostar no que você tem aberto.

Uma worktree é um projeto

A decisão sobre a qual esta página é construída

Criar uma worktree cria um projeto. Abrir ela abre em todo lugar: a Revisão dentro dela compara contra o branch daquela worktree, os Arquivos navegam aquele checkout, sessões começam naquele diretório, e ela tem a própria Memória.

Não existe código específico de worktree nas superfícies de arquivo, editor, Revisão ou Git. Essa ausência é a evidência de que a decisão tinha o formato certo.

Nomes de branch viram nomes de pasta, com segurança

Um branch chamado agent/login-form viraria um diretório aninhado se o nome fosse usado literalmente. A barra vira um traço: agent-login-form. Verificado criando exatamente esse branch e confirmando uma pasta única e plana em vez de uma árvore de diretórios.

Remover uma pergunta duas vezes, por dois motivos diferentes

Vale entender porque parece uma confirmação duplicada e não é.

  1. O Git recusa, porque tem trabalho não commitado

    Isso é informação, e merece uma resposta simples: remover assim mesmo, ou não. Nada de proteções está envolvido ainda.

  2. A remoção forçada é uma operação protegida

    Só agora o fs.recursive-delete entra em jogo, e só agora as escolhas da proteção são oferecidas.

O --force nunca é passado especulativamente. A primeira tentativa é a honesta, e a tentativa forçada só acontece porque você disse.

Remover uma worktree arquiva a linha de projeto dela em vez de apagar — as sessões que rodaram ali, e o histórico delas, continuam seus.

Por que isso importa para agentes

Um agente trabalhando numa worktree não consegue quebrar o checkout que você está lendo, não consegue deixar sua árvore de trabalho suja, e não consegue brigar com você por um arquivo. Combinado com Sem supervisão, é a montagem em que deixar uma execução rodando é genuinamente de baixo risco.

Uma armadilha, e ela é tratada

Uma worktree é sempre uma pasta nova em folha, e o Claude Code pergunta se você confia numa pasta na primeira vez que abre uma. Uma execução sem supervisão iniciada numa worktree nova ficaria travada para sempre numa pergunta que ninguém está presente para responder. Iniciar é recusado, com o motivo — veja Autonomia.
