Você vai deixar um agente rodando enquanto faz outra coisa. As proteções são o que torna isso uma decisão razoável: nove classes de operação que são paradas e retidas para uma decisão antes de executarem.

Três respostas, resolvidas por uma cadeia

Cada operação recebe Sempre perguntar, Permitir ou Nunca permitir, resolvidas projeto → global → padrão. O padrão é Perguntar. A cadeia tem o mesmo formato que a autonomia usa, de propósito.

Permitir é silêncio, não permissão

Permitir quer dizer que a proteção não faz objeção. Não quer dizer que a operação foi revisada, e não quer dizer que ela é segura. A distinção está escrita no código ao lado do enum, porque quem confundir as duas vai desenhar o próximo recurso errado.

Onde dá para aplicar de verdade — e onde não dá

Esta é a parte que a maioria das ferramentas exageraria discretamente. O modelo de capacidades informa a verdade por situação:

SituaçãoO que acontece
Um comando de verificação que o J.A.R.V.I.S. roda para uma missão Aplicação real. O processo é nosso.
Uma sessão do Claude Code Aplicação real, pelo hook pré-ferramenta dele. Verificado contra a 2.1.240: um push forçado foi recusado antes de executar.
Uma sessão do Codex Mesmo mecanismo de hook, mas o Codex não executa ele até você confiar nele na interface do próprio Codex. Informado como PreExecutionWhenTrusted — observado, não protegido, até você fazer isso.
Uma pessoa digitando num terminal Nada, deliberadamente. As proteções governam agentes. Seu terminal é seu terminal.

Ela falha aberta, e essa é a escolha certa

Sem snapshot de política, JSON malformado, ou uma versão que a proteção não entende: ela fica em silêncio e a chamada de ferramenta prossegue.

Isso parece invertido até você fazer a conta. O processo da proteção roda antes de toda chamada de ferramenta em toda sessão de agente. Uma proteção que falhasse fechada transformaria qualquer bug nela mesma — um arquivo faltando, um erro de parse, uma diferença de versão depois de uma atualização — em um agente que não consegue fazer nada, em todo projeto, até alguém diagnosticar. Falhar aberta faz um bug te custar a proteção; falhar fechada faz um bug te custar o produto.

Como o classificador decide

É casamento heurístico sobre o texto do comando: ele tokeniza, respeita aspas, e lê cada programa com seus argumentos. Ele não é um parser de shell e não finge ser.

Leia esta frase duas vezes

Um comando que o classificador não sinaliza não foi provado seguro. Ele falhou em casar com um padrão. São afirmações diferentes, e só uma delas é verdadeira.

Os casos negativos são os que sustentam tudo. Estes não podem casar, ou a proteção vira a primeira coisa que qualquer um desliga:

✓ não casa  git push --force-with-lease origin main
            se recusa sozinho quando o remoto mudou — a grafia segura

✓ não casa  echo "rm -rf /tmp/x"
            uma string sendo impressa, não um diretório sendo apagado

✓ não casa  npm publish --dry-run
            não publica nada

✓ não casa  cat .env.example
            um arquivo de exemplo não é uma credencial

✗ casa      pnpm build && git push --force && npm publish
            uma cadeia não é um comando; cada parte é classificada

Onde um descarte é protegido e um stage não é

Dentro da Revisão, só o descarte é uma ação protegida. Adicionar e remover do índice mexem no índice e são reversíveis; perguntar sobre eles te ensinaria a desligar a proteção, e aí o descarte também fica desprotegido. Proteger tudo é como se acaba não protegendo nada.

A trava ali também nomeia a operação dela em vez de classificar uma string de comando que ela mesma acabou de montar, e não escreve linha pendente nenhuma — você está na tela, então a pergunta é feita e respondida ali.

Em Sem supervisão, "perguntar" recusa

Uma regra em Perguntar não consegue perguntar para ninguém durante uma execução sem supervisão. Em vez de estacionar o agente num prompt que ninguém vai responder, a proteção recusa, e a missão vai para Esperando com um motivo. A sessão avisa à proteção que é dirigida, e é assim que a proteção sabe.

Verificado contra um agente real

Contra o Claude Code 2.1.240 real: um push forçado foi recusado antes de executar, e em Sem supervisão um rm -rf foi parado com o diretório ainda lá depois. Separadamente, no app instalado: uma missão cujo critério de aceitação era npm publish teve a checagem retida em vez de executada, a aprovação foi respondida, e a missão saiu de Esperando.

Dentro da proteção explica o mecanismo — um processo separado, um snapshot em disco, e decisões anexadas a um arquivo que a sessão acompanha.
