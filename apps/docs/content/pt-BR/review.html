Você deixou um agente trabalhando e voltou. A Revisão responde a única pergunta que importa: o que ele mudou de verdade?

O Git decide o que mudou

A regra

git status --porcelain=v1 -z para a lista. git diff -M HEAD para os blocos. A gente analisa; a gente nunca calcula um diff por conta própria torcendo para ele concordar com o seu git.

O -M é por que um arquivo renomeado aparece como uma linha alterada em vez de um arquivo inteiro apagado mais um arquivo inteiro adicionado — verificado renomeando um arquivo e lendo o resultado, não presumido da documentação da flag.

A atribuição é um join, não uma invenção

A Revisão consegue te dizer qual agente mudou um arquivo. Ela não precisa de um livro separado para isso: o log da sessão já registra um quadro FileChange para todo arquivo que uma sessão tocou, então a resposta é uma consulta sobre dados que já estavam sendo escritos de qualquer jeito.

Um arquivo mudado por uma sessão real do Claude Code aparece no topo da lista, atribuído ao Claude Code. Um arquivo que você mesmo mudou é simplesmente um arquivo que nenhuma sessão reivindica.

Operações de escrita do Git

Adicionar ao índice, remover do índice, descartar, restaurar e commitar — tudo daqui, tudo rodando Git de verdade.

AçãoProtegida?Por quê
Adicionar · Remover do índiceNãoMexem no índice e são reversíveis.
CommitarNãoReversível, e o Git guarda cópia de tudo que está dentro.
Restaurar um arquivo apagadoNãoCria; não destrói.
Descartar mudançasSim — git.discard-changesA única coisa da qual o Git não guarda cópia.

Proteger só o descarte é uma escolha deliberada, e o raciocínio se generaliza: perguntar sobre adicionar ao índice te ensinaria a desligar a proteção, e aí o descarte também fica desprotegido. Proteger tudo é como se acaba não protegendo nada.

A trava nomeia a operação dela

A Revisão não monta uma string de comando e depois entrega ao classificador para descobrir o que ela mesma acabou de decidir fazer. Ela nomeia a operação diretamente. E não escreve linha pendente nenhuma — você está na tela, então a pergunta é feita e respondida ali mesmo em vez de virar algo para resolver depois.

Toda grafia de Git foi conferida antes de ser escrita

O git restore simples restaura a partir do índice, então um descarte construído em cima dele mantém conteúdo staged em silêncio — você apertaria descartar, veria a árvore de trabalho mudar, e ainda teria a versão staged parada ali. O descarte daqui vai até o HEAD, e isso foi confirmado em disco descartando um arquivo que carregava mudanças staged e de árvore de trabalho ao mesmo tempo.

Dentro de uma worktree

A Revisão dentro de uma worktree compara contra o branch da própria worktree. Não existe código específico de worktree aqui — uma worktree é um projeto, então funciona porque todo o resto já funciona.

Verificado no app instalado

Um arquivo foi adicionado e removido do índice; um arquivo com mudanças staged e de árvore de trabalho foi descartado e confirmado em disco como tendo chegado ao HEAD; um arquivo apagado foi restaurado; três arquivos staged foram commitados. Depois Nunca permitir foi definido para descarte e o descarte seguinte foi recusado com a árvore de trabalho intocada. Os dois temas, os dois idiomas.
