Navegue pelo projeto, abra um arquivo, edite, salve. A parte interessante não é o editor — é o que acontece quando um agente está escrevendo no mesmo arquivo que você tem aberto.

A árvore

Entradas ignoradas pelo Git são esmaecidas em vez de escondidas — você ainda consegue abrir uma quando precisa, e enxerga de relance quais partes da árvore são geradas. O próprio .git não é listado.

Todo caminho é confinado à raiz do projeto, conferido duas vezes: uma no formato da requisição, e outra no caminho resolvido contra o sistema de arquivos real.

O editor

Monaco, com destaque de sintaxe, e CtrlS para salvar. Ele vem sem os serviços de linguagem, deliberadamente.

Por que não existem rabiscos vermelhos

Os workers de TypeScript, CSS, HTML e JSON do Monaco estão excluídos porque seriam confiantemente errados sem contexto de projeto — sem tsconfig, sem node_modules, sem aliases de caminho. Diagnósticos que você tem que aprender a ignorar são piores do que diagnóstico nenhum. Os de verdade chegam com um language server; a fronteira para ele já está na arquitetura.

O custo de deixá-los de fora foi medido no instalador real, não estimado: +1,04 MB.

Um save não vai sobrescrever um agente em silêncio

Esta é a parte que importa mais aqui do que em um editor comum, porque este produto existe para que um agente possa estar trabalhando em uma aba enquanto você lê em outra. O conflito é o caso normal, não um caso de borda.

O editor lembra a data de modificação do arquivo quando ele foi aberto. O núcleo recusa uma escrita quando o arquivo no disco não é mais o que foi aberto:

  • Nada é escrito.
  • Seu buffer fica intocado — sem merge, sem recarga, sem digitação perdida.
  • A superfície diz o que aconteceu e nomeia as duas saídas.

Salvar de novo sobrescreve, deliberadamente. Depois de avisado, a decisão é sua.

Fechar uma aba suja pergunta antes

Fechar descarta o modelo, e o histórico de desfazer vai junto. Um clique só não pode conseguir destruir uma edição que o pontinho de "não salvo" estava anunciando.

Fins de linha não são reescritos

Um arquivo salvo deste editor mantém os fins de linha que tinha. Isso foi verificado em disco, não presumido — um editor que converte LF para CRLF em silêncio numa máquina Windows transforma uma mudança de uma linha em um diff de arquivo inteiro, e faz isso com todo arquivo que você toca.

Verificado no app instalado

A árvore foi navegada com node_modules e build.log esmaecidos e .git ausente. Um arquivo foi aberto, editado, salvo com CtrlS, e confirmado em disco com o conteúdo alterado e os fins de linha LF inalterados. Os dois temas fotografados.

Um atalho que o editor abre mão

CtrlK é resolvido globalmente, antes de qualquer widget ver. O Monaco trata ele como prefixo de acorde e chamava stopPropagation, então a paleta de comandos parava de abrir em silêncio sempre que o editor tinha o foco — enquanto a barra de título seguia anunciando o atalho.

Agora ele é tratado na fase de captura. O efeito colateral é real e vale declarar: o Ctrl+K não chega mais a um shell como o matar-até-o-fim-da-linha do readline. É a mesma troca que o VS Code e o Cursor fazem, e ela é documentada em vez de deixada para você descobrir.
