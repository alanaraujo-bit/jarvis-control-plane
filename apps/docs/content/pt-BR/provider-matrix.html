Toda capacidade que os adaptadores declaram, o que cada valor significa para você, e como foi estabelecido. Os valores são lidos de providers/claude.rs e providers/codex.rs.

Isto são dados, não documentação

Cada adaptador devolve isto como uma struct, e a interface renderiza a partir dela. Nada aqui é um booleano escrito dentro de um componente, e é por isso que adicionar um terceiro provedor não exige encostar em um único arquivo React. Um teste falha se os dois adaptadores algum dia se descreverem de forma idêntica.

O que cada valor significa

Correlação de sessão

Deterministic
O provedor aceita um id de sessão que nós escolhemos e escreve a transcrição com esse nome. O vínculo é um fato que nós afirmamos. Claude Code: --session-id <uuid>.
FileWatch
O provedor nomeia os próprios arquivos, então o adaptador observa o diretório e casa com o que apareceu depois que este processo começou. Uma heurística muito boa, e ainda assim uma heurística — duas sessões iniciadas no mesmo segundo na mesma pasta é onde ela poderia errar. Informado honestamente em vez de enfeitado.

Aplicação de proteções

PreExecution
Aplicação real. Uma recusa realmente para o comando antes de ele rodar. Verificado contra o Claude Code 2.1.240 recusando um push forçado real e confirmando que o remoto ficou intocado.
PreExecutionWhenTrusted
O mesmo mecanismo de hook, mas o provedor não executa um hook até você ter revisado e confiado nele na interface dele. O J.A.R.V.I.S. escreve a configuração no início da sessão para que ela esteja lá para ser confiada. Até você fazer isso, aquela sessão é observada, não protegida, e a interface diz isso.

Rota do briefing

SystemPrompt
O briefing é passado fora de banda, como um prompt de sistema anexado, lido de um arquivo que é nosso. Nada é escrito no seu repositório, nenhum turno é gasto, e nada aparece no terminal. Claude Code: --append-system-prompt-file.
OpeningMessage
Não existe rota fora de banda, então um briefing só poderia chegar como a mensagem de abertura da sessão — visível no terminal e custando um turno. Codex 0.147.0: o --help dele não lista equivalente, e instruções chegam como argumento de prompt ou pela entrada padrão. Informado em vez de maquiado, porque uma pessoa escolhendo provedor para uma execução sem supervisão deveria saber qual das duas está levando.

Títulos de sessão

Provider
Ele nomeia as próprias sessões. O Claude Code escreve uma linha ai-title — presente em 89 das 124 transcrições da máquina em que isso foi verificado.
Derived
Ele não declara título, então um é calculado a partir do que foi dito. O Codex 0.147.0 está aqui; set_thread_title existe nos rollouts dele, mas como definição de ferramenta dentro das instruções, e não como evento que ele emite — conferido em todos os rollouts daquela máquina.

Mecanismo de retomada

Fork
--resume <id> --fork-session honra o nosso próprio id de sessão e escreve uma transcrição nova com esse nome — então a continuação é uma sessão que conseguimos acompanhar desde o começo. Verificado no Claude Code 2.1.241.
AppendInPlace
codex resume <id> anexa ao rollout que ele recebeu em vez de criar um. Um formato diferente, medido na 0.147.0, e a interface diz isso em vez de fingir que os dois são iguais.

As duas também foram rodadas contra um diretório de configuração vazio antes de o recurso ser construído: as duas leem a conta do diretório para o qual são apontadas, e as duas falham dizendo isso em vez de devolver os números da conta ambiente com o nome errado. Isso é mantido como teste de segurança permanente — se algum dia ele passar como Ok, o recurso está atribuindo cotas erradas e precisa ser desligado.

Quando uma página diz que uma capacidade se comporta de certa forma, é nessas versões. Uma capacidade afirmada a partir de uma listagem de --help seria uma afirmação sobre documentação e não sobre comportamento, e é por isso que as que sustentam o produto são fixadas por testes que iniciam um agente real através de um terminal real.
