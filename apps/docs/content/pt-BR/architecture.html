Quatro fronteiras que sustentam o desenho

1. O log da sessão é o único depósito de registro

Tudo depois dele é uma projeção. Não existe um segundo depósito que possa discordar do primeiro, e qualquer coisa que precise contribuir entrega a contribuição ao escritor único em vez de escrever ao lado dele.

2. Capacidades são dados

Um adaptador de provedor se descreve com uma struct, e as superfícies renderizam a partir dela. Adicionar um provedor não pode exigir encostar em um componente — e se exigisse, a abstração já teria falhado. Um teste falha se dois adaptadores algum dia se descreverem de forma idêntica.

3. O Git decide o que o Git sabe

Status, diffs, branches, worktrees: a gente roda o binário git e analisa. A gente nunca calcula um diff por conta própria torcendo para ele concordar com o git do usuário. O único lugar em que isso quase deu errado é instrutivo — o git restore simples restaura a partir do índice, então um descarte construído em cima dele mantém conteúdo staged em silêncio.

4. O webview nomeia caminhos, o núcleo resolve

Toda requisição de arquivo é relativa a uma raiz de projeto lida do banco, nunca um caminho que quem chamou forneceu. Duas checagens independentes vêm depois, e a segunda reconfere o caminho resolvido contra o sistema de arquivos para pegar um symlink apontando para fora do projeto.

O padrão de dois processos

Duas vezes neste produto, alguma coisa precisa participar de uma sessão sem conseguir corrompê-la. As duas usam o mesmo formato:

Um provedor entrega a transcrição dele assim. A proteção entrega as decisões dela do mesmo jeito. Nenhum dos dois consegue reordenar o log, descartar um quadro ou competir com o escritor, porque nenhum dos dois é o escritor.

A interface não é dona de nada

Toda decisão relevante mora em Rust: quais caminhos são alcançáveis, se um valor está na faixa, se uma operação é protegida, quando um turno acabou, o que um provedor consegue fazer.

Por que os limites são reconferidos no núcleo

A superfície desenha um controle deslizante, então um valor fora da faixa deveria ser impossível — que é exatamente por que ele não é confiado. Um comando alcançável pelo webview é alcançável por qualquer bug dentro do webview. Fora da faixa na entrada é recusado; fora da faixa na saída é limitado.

Para onde isso vai

Duas fronteiras foram deixadas deliberadamente abertas. Um cliente de language server, porque o Monaco vem sem os serviços de linguagem dele e diagnósticos de verdade precisam de contexto de projeto. E um terceiro provedor, porque o modelo de capacidades existe justamente para que adicionar um seja um adaptador e não uma refatoração.

Dentro da proteção Um processo separado, um snapshot, um classificador que tokeniza, e uma decisão anexada a um arquivo. Dentro do piloto automático Um planejador puro e um driver que toca o mundo.
