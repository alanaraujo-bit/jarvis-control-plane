Ten minutes, one real project, and an agent that finishes something you can prove it finished. Nothing here is a toy: every step runs against your own code.

  1. Open a folder

    Go to Projects on the rail and choose Open folder. Pick a real repository. J.A.R.V.I.S. asks Git whether it is a repository and which branch you are on; it does not create or modify anything.

  2. Tell the project what it is

    Open the project, go to Brain, and write three or four things an agent would otherwise get wrong. The port your dev server actually uses. The convention nobody writes down. The word your team uses differently.

    This is the highest-leverage two minutes in the product. Every agent that starts in this project from now on is told these before it reads a single file, and it costs nothing per session. See Memory.

  3. Start an agent

    In Sessions, press + and choose Claude Code or Codex. You get a real terminal — the same CLI, the same keys, the same behaviour — running in the project directory.

    Ask it for something small and real. A failing test fixed. A function documented. Anything with a check you could run afterwards.

  4. Flip to Conversation while it works

    Press the toggle. The process is not touched and nothing restarts. You get structured turns, the tools it called, and the provider's own token counts for each turn — not an estimate, the numbers the provider stated.

    Flip back whenever you want to type. See The session event log for why this works at all.

  5. Write a mission with a check that can fail

    Go to Missions and create one. Give it an acceptance criterion of kind Command — your test suite, a lint run, a build. Something that genuinely fails today.

    Then try to complete the mission. It will refuse, and it will name the criterion that does not hold. That refusal is the feature.

  6. Let the agent do the work, then verify

    Back in the session, ask the agent to make the check pass. When it says it is done, run verification on the mission. The command actually runs, its exit code is compared with the one you expected, and its real output is stored as evidence.

    Now completion is allowed. See Missions.

  7. Break it on purpose

    Undo the change — delete the file, revert the fix. Re-verify. The completion is revoked, because the evidence stopped holding.

    This is the difference between a mission and a checkbox. A checkbox records that somebody once believed something. A mission records whether it is currently true.

  8. Look at what just happened

    Review shows what changed, attributed to the session that changed it. Activity shows the sequence of events. Analytics shows what it cost in tokens and in your own time. History shows the session, titled, and lets you reopen it read-only months from now.

Three things to try next

Stop a dangerous command Set one rule and watch a force push be refused before it runs. Walk away from a run Set a mission to Unattended and let the autopilot verify after every turn. Keep your prompts somewhere real CtrlShiftN from anywhere, and one button sends a note into the agent you are watching.

Two keys worth learning now

CtrlK
The command palette. Every destination, every settings section, every action, ranked by subsequence — type mc and get Mission Control.
CtrlShiftF
Global Search, across every project: knowledge, notes, missions, activity, and what was actually said in any conversation you have ever had.

The full list is short, and it says which key the product takes away from your shell and why.
