Four boundaries that carry the design

1. The session log is the only store of record

Everything downstream is a projection. There is no second store that can disagree with the first one, and anything that needs to contribute hands its contribution to the single writer rather than writing alongside it.

2. Capabilities are data

A provider adapter describes itself with a struct, and surfaces render from it. Adding a provider must never require touching a component — and if it did, the abstraction would already have failed. A test fails if two adapters ever describe themselves identically.

3. Git decides what Git knows

Status, diffs, branches, worktrees: we run the git binary and parse it. We never compute a diff ourselves and hope it agrees with the user's own git. The one place this was nearly got wrong is instructive — plain git restore restores from the index, so a discard built on it silently keeps staged content.

4. The webview names paths, the core resolves them

Every file request is relative to a project root read from the database, never a path the caller supplies. Two independent checks follow, and the second one re-checks the resolved path against the filesystem so a symlink pointing out of the project is caught.

The two-process pattern

Twice in this product, something needs to participate in a session without being able to corrupt it. Both use the same shape:

A provider hands over its transcript this way. The guardrail hands over its decisions the same way. Neither can reorder the log, drop a frame, or race the writer, because neither is the writer.

The interface owns nothing

Every meaningful decision lives in Rust: which paths are reachable, whether a value is in range, whether an operation is guarded, when a turn ended, what a provider can do.

Why bounds are re-checked in the core

The surface renders a slider, so an out-of-range value should be impossible — which is exactly why it is not trusted. A command reachable from the webview is reachable from any bug in the webview. Out of range on the way in is refused; out of range on the way out is clamped.

Where it is going

Two boundaries were left deliberately open. A language server client, because Monaco ships without its own language services and real diagnostics need project context. And a third provider, because the capability model exists precisely so that adding one is an adapter rather than a refactor.

Inside the guardrail A separate process, a snapshot, a tokenising classifier, and a decision appended to a file. Inside the autopilot A pure planner and a driver that touches the world.
