Browse the project, open a file, edit it, save it. The interesting part is not the editor — it is what happens when an agent is writing to the same file you have open.

The tree

Git-ignored entries are dimmed rather than hidden — you can still open one when you need to, and you can see at a glance which parts of the tree are generated. .git itself is not listed at all.

Every path is confined to the project root, checked twice: once on the shape of the request, and once on the resolved path against the real filesystem.

The editor

Monaco, with syntax highlighting, and CtrlS to save. It ships without its language services, deliberately.

Why there are no red squiggles

Monaco's TypeScript, CSS, HTML and JSON workers are excluded because they would be confidently wrong without project context — no tsconfig, no node_modules, no path aliases. Diagnostics you have to learn to ignore are worse than no diagnostics. Real ones arrive with a language server; the boundary for it is already in the architecture.

The cost of leaving them out was measured on the real installer, not estimated: +1.04 MB.

A save will not silently overwrite an agent

This is the part that matters here more than in an ordinary editor, because this product exists so that an agent can be working in one tab while you read in another. The conflict is the normal case, not an edge case.

The editor remembers the file's modification time when it opened it. The core refuses a write when the file on disk is no longer the one that was opened:

  • Nothing is written.
  • Your buffer is untouched — no merge, no reload, no lost typing.
  • The surface says what happened and names the two ways out.

Saving again overwrites, deliberately. Once you have been told, the decision is yours.

Closing a dirty tab asks first

Closing disposes the model, and the undo history goes with it. A single click must not be able to destroy an edit the dirty dot was advertising.

Line endings are not rewritten

A file saved from this editor keeps the line endings it had. This was verified on disk rather than assumed — an editor that silently converts LF to CRLF on a Windows machine turns a one-line change into a whole-file diff, and does it to every file you touch.

Verified in the installed app

The tree was browsed with node_modules and build.log dimmed and .git absent. A file was opened, edited, saved with CtrlS, and confirmed on disk to have changed content and unchanged LF line endings. Both themes screenshotted.

One shortcut the editor gives up

CtrlK is resolved globally, before any widget sees it. Monaco treats it as a chord prefix and called stopPropagation, so the command palette silently stopped opening whenever the editor had focus — while the titlebar went on advertising the shortcut.

It is now handled in the capture phase. The side effect is real and worth stating: Ctrl+K no longer reaches a shell as readline's kill-to-end-of-line. That is the same trade VS Code and Cursor make, and it is documented rather than left for you to discover.
