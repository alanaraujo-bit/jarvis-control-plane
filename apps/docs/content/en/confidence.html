Software that works with agents is full of numbers nobody can check. Token counts, remaining allowance, whether an agent is waiting on you, what it is asking for. Most tools present all of it in the same typeface and let you assume it is all equally true.

J.A.R.V.I.S. does not. Every number and every claim travels with a label saying where it came from, and the label is stored with the value rather than decided by whichever screen is drawing it.

Four levels

Official
The provider stated it. A token count from assistant.message.usage, a rate limit from event_msg/token_count, an agent's own reply. If this is wrong, the provider was wrong.
Observed
Measured by J.A.R.V.I.S. from something the provider emitted, but not stated by it. A question read off a terminal is the clearest case: the agent asked it, but no structured event says so.
Estimated
Derived or extrapolated. An allowance learned from this machine's own past refusals is the main one — a real number, computed from real evidence, and still not a published figure.
Unknown
Nothing supports a value. Shown as unknown rather than as zero, because zero is a number and this is the absence of one.

Where you will actually see it

On a notification

A finished turn, a guardrail decision, a mission completing and a run stopping are Official — something stated them. A question read off a terminal is Observed, and the notification says so in words: Read from the terminal against Reported by the agent.

That difference is not decoration. Claude Code asking whether it may write a file is stated nowhere: the guardrail hook returns early for anything that is not a classified shell command, and the transcript records the answer rather than the question. The only way to know is to read the terminal, and the only honest thing to do is say that is what happened.

On an account's quota

This is where the rule was most expensive to keep, and where keeping it later paid.

An early pass read all 115 transcripts on the development machine and established something true: Claude Code states its quota only in the turn it refuses. A rejection is Official and exact to the second; everything before it is Observed at best. So the panel was built to be impeccably honest, and it therefore said allowance unknown nearly everywhere — sending the user back to the web UI the feature existed to replace.

The finding was true about transcripts and false about the providers. Both CLIs answer a live usage question on a supported protocol — get_usage on Claude Code's stream-json control channel, account/rateLimits/read on codex app-server. Those answers are Official, and the honest panel became a useful one without ever having to fudge a number.

On evidence for a mission

A mission is completed on evidence, and evidence is the outcome of a real command or a real file check. A criterion nobody can automate is a Manual one, and its evidence reads confirmed by {who} rather than passed. The distinction survives into the database rather than living only on screen.

On an estimate that is allowed to exist

The implied allowance is learned from any official percentage the provider gives — if a reading says 29% used and states the tokens behind it, the total can be inferred. It is labelled Estimated, and it exists precisely so the fallback stops needing the refusal it is there to prevent.

Why the label travels with the value

A Usage frame in the session log carries its confidence in the frame. It is not recomputed when a screen renders and it is not attached by the surface that happens to be displaying it.

The reason is dull and decisive: a level decided at the UI layer is a level that two different screens can decide differently. The moment Analytics and the Accounts panel disagree about whether a number is official, both of them are untrustworthy — not just the one that is wrong.

What the product will not do

It will not show an estimate in the same weight as a measurement. It will not fill an unknown with a plausible default. It will not translate an agent's own words and present them as if the agent said them in your language. And it will not report a guardrail as enforcing when the provider has not agreed to run the hook.

The honest failure this produces

Being strict about provenance means the interface sometimes has to say it does not know. A Codex account signed in on 0.149.1 writes no identity at all, so it has no name to show — and the product says the name is unknown instead of inventing one from the directory it lives in.

That is the trade. A product that never says unknown is not a product that always knows.
