If you pay for more than one subscription, you already know the failure: the one you are using runs out mid-task, and the other three sit idle because nothing tells you they exist or which of them has room.

An account is a configuration directory

This is the identity model, and everything follows from it. An account is a provider configuration directory — CLAUDE_CONFIG_DIR for Claude Code, CODEX_HOME for Codex. Register a directory, and the credentials inside it are that account.

Nothing here ever rewrites your credentials

The account already signed in on this machine is adopted, never copied. Rewriting one global credential file would log you out of the session you are sitting in front of, and it could not let a running session finish on the old account while new work starts on the next one — which is the entire point.

That is also why a switch is cheap: pointing a new session at a different directory is a different environment variable, not a login.

What the panel answers

How much is left
A dial showing what remains, not what has been consumed. You are deciding whether to start something, so the useful number is the one you have.
When it comes back
Both a countdown and the wall-clock moment. 56m answers "can I wait?"; 13:10 answers "should I go to lunch?".
Which limit is binding
A session window and a weekly window are different limits and either can be the one stopping you. The binding one says this is the limit holding you up and is drawn larger.
Where new work should start
A strip at the top names the account with room, so the answer is on screen before you have to work it out.

Live readings, and how they are obtained

Both CLIs answer a usage question on their own supported protocol: get_usage on Claude Code's stream-json control channel, and account/rateLimits/read on codex app-server. Measured against the real binaries, not remembered from a doc page.

What a probe does not do, and this was checked: no HTTP endpoint of our own, no reading of your credential files, no token spent, no transcript written.

The check that decided the scope, before anything was built

Each probe was run against an empty configuration directory. Both read the account in the directory they are pointed at, and both fail by saying so rather than returning the ambient account's numbers under the wrong name. That is kept as a safety test — and if it ever passes as Ok, the feature is misattributing allowances and must be turned off.

Switching

Automatic switching has three settings:

  • Off — you choose, always.
  • When exhausted — new work moves once the provider says an account is out.
  • Near the limit — new work moves before it runs out.

Running sessions keep their account. A switch changes where new work starts; it never yanks the directory out from under an agent that is mid-task.

Continuity across a switch

An agent moved to a new account cannot be resumed with --resume, because a resume cannot cross configuration directories. Continuity is carried by the Brain brief instead — the new session starts knowing what the project knows, which is the part that actually mattered.

Two directories, one subscription

This one was found by looking at the screen. Three Claude cards, two showing identical statistics under different names. They were not duplicated readings: claude auth status --json against each directory settles it — two of the directories were the same email under the same organisation. One allowance, drawn twice. The numbers were the only honest thing on that screen; the two names were the lie.

How it is handled now:

  • Keyed on email, not organisation. A Team plan puts several people's separate allowances under one org, so org identity would merge accounts that are genuinely different.
  • An absent email is unknown, never same. Codex 0.149.1 writes no identity at all, and guessing here would merge two real accounts.
  • The bug half. Automatic switching treated a twin as a destination. When exhausted was protected by accident; near the limit was not, and would ping-pong new work between two views of one window — on the exact setting somebody turns on to have this handled for them.
  • Told, not prevented. Two directories on one account is legitimate. Signing in is not refused and nothing is hidden; both cards say what they are, above the dial rather than under it.

Nothing about this is stored. The adopted row is read with the ambient environment, so a twin_of column would be a fact that goes stale silently.
