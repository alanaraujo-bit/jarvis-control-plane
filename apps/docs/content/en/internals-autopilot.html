The autopilot takes the human's seat during an unattended run. This page is how it is built; the guide is how to use it.

Two halves, split along one line

ModuleIsTouches
autopilot::plan A pure function of mission state Nothing. No processes, no database, no clock.
autopilot::driver The part that acts Processes, the database, the clock.
Why the split is exactly there

What to say and when to stop is the part that must never be subtly wrong. A planner that decides to keep going when it should stop burns your tokens; one that stops when it should continue wastes the run. So that decision is a pure function, testable in isolation, against constructed mission states rather than against a live agent.

Everything that can fail for environmental reasons lives on the other side of the line.

The loop

The stopping condition comes from the provider

Never from a quiet terminal

Silence means nothing. The agent might be thinking, waiting on a network call, or about to print another thousand lines. Inferring the end of a turn from quiet would make the autopilot interrupt an agent mid-thought, repeatedly, and burn the budget on partial work.

Claude Codestop_reason: "end_turn" — and "tool_use" explicitly means it is still working
Codexevent_msg/task_complete

Both are projected into the same conversation item, so the driver never has to know which provider it is steering. This was checked across every transcript on the development machine: 664 turn boundaries, none of them a tool_use.

Three endings, and no fourth

EndingWhen
CompletedEvery required criterion verified, with evidence.
Waiting · BlockedA guardrail held something, or the agent hit something it cannot do. Always with a reason.
FailedThe turn budget is spent, or the same criteria keep failing. Always with a reason.

Keep going and hope is what a run does when the model gives it nowhere honest to stop. Leaving it out is the whole reason the other three are trustworthy.

The next instruction names what does not pass

Each instruction after the first is built from the verification that just ran: it says which criteria still fail, and what they were checking. An agent told keep going has to guess what is missing; an agent told these two commands still exit non-zero does not.

The timing detail that would have been a silent bug

A turn's last frames can still be arriving

When the provider reports the turn ended, the log's trailing frames may not all have landed. So the driver settles briefly before reading, and the constant that does it exists for exactly that reason.

The same risk appeared one turn later, in the reflection question the agent is asked at the end of a completed run. Its reply window originally started at the cursor the work turn's own turn-end left behind — so a straggler frame from the previous turn could be read as part of the answer. Fixed by re-baselining to the log's current end immediately before the question is sent, pinned by a test with a deliberately planted straggler, and then reconfirmed against a real agent.

What a driven run changes elsewhere

Guardrails refuse instead of asking
The session reports driven: true, so an ask rule becomes a refusal rather than a prompt nobody can answer. See Inside the guardrail.
Finished turns stop notifying
Twenty notifications while somebody is away by choice, then a twenty-first that is the only one they wanted, at the bottom of a pile. Questions are still raised, because a driven agent that stops to ask cannot continue.
Starting is refused in an untrusted folder
Claude Code asks whether you trust a folder the first time it opens one. A fresh worktree is always a new folder, so this became reachable the moment worktrees shipped. Refusing beats hanging forever on a question nobody is present to answer.
The agent is asked what it learned
Once, at completion only. Step::Complete is the one place a driven run holds the seat with nobody else in it — a manually completed mission is never asked, because typing a question into a terminal somebody is watching is a different conversation to interrupt. See Project memory.

The budget

4 to 100 turns, default 24, read from Settings. A run keeps the budget it started with — re-reading it each turn would let a change in Settings move the finish line under a run already going.

Stopping a run does not kill the agent

Somebody taking over usually wants to type the next thing themselves, and killing the process would throw away its context. The autopilot stands down and leaves a live session at a prompt.
