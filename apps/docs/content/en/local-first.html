Local-first is easy to claim and easy to erode. This page is the specific version: what stays, what can leave, what leaving actually means, and how to turn it off.

What never leaves

Your code and your Git
J.A.R.V.I.S. opens folders that are already on your disk. It runs the git binary you already have. It does not clone, mirror or upload anything.
Your terminals
Real pseudo-terminals, real processes, on your machine. Every byte written by every agent lands in a file under your own data directory.
Your credentials
Provider credentials are read by the providers, from the configuration directories they already use. J.A.R.V.I.S. points a session at a directory; it never opens the credential file, and it never rewrites one.
Your history
Every session ever run, its conversation, its token counts, its evidence, its activity — in a SQLite database and a folder of session logs on your disk. See Where your data lives.
Your voice
Dictation runs whisper.cpp locally. There is no cloud speech API and no key to configure. The audio never leaves the machine.

There is no account to create. Nothing is uploaded in order to use the product, and the product works with no network connection at all except the one the agents themselves need.

What the agents do on their own

Claude Code and Codex talk to their own providers, on their own terms, using your own credentials. That traffic is theirs.

Worth being precise about

J.A.R.V.I.S. does not proxy an agent's traffic. It launches the CLI you already have and reads the JSONL transcript that CLI writes to disk. There is no man in the middle, which also means there is no place for one to be added later without you noticing a new network connection.

The one thing that can leave, and exactly what it is

The phone relay. It is off unless you pair a device, and it exists to answer one question from another room: is anything waiting on me?

A blind mailbox, not a server that knows things

The relay is three endpoints. The desktop pushes a summary and collects queued commands; the phone reads the summary and queues an answer. The relay stores only a hash of each token. Turn it off and the desktop is untouched — which is the test of whether local-first survived the introduction of a cloud at all.

A summary, never a mirror

What is sent is what needs a person, and nothing else.

SentNever sent
That something is waiting, and what class of thing it is File contents
Which project and which session, by name Terminal output
What is running right now Conversation text
The device name, so you know which machine you are looking at Your code, your diffs, your credentials

A relay holding a copy of the work would be exactly the second store that the session log exists to prevent.

Pairing, and why it is a six-character code

No account. A six-character code, single use, valid for five minutes, with attempts counted. Three constraints doing the work together — and one of them was found broken by reading: the pairing endpoint declared an attempts counter, checked it, and never incremented it. A limit that could not be reached.

Only one answer is reachable from a phone

Guardrails offer four answers and three of them write a lasting policy — including Never allow. A phone has a small screen and a thumb, so it gets the one answer that expires with the thing it answers: allow once.

Refusing from a phone is simply not approving. The guardrail already refuses by default, so the safe outcome needs no button at all.

Everything expires, enforced on read

A serverless relay has no process to sweep in and delete things. So expiry is checked when a value is read, and an expired value is never served even if nothing has cleaned it up. Commands expire far sooner than snapshots, because a stale approval is worse than a stale status.

Disconnect had to be fixed to mean disconnect

Found by running it: clearing the local pairing left the mailbox standing, and a paired phone kept reading. A switch that leaves a live token working is worse than no switch at all. Disconnect now revokes.

Turning it off

Settings → Phone. The section says what is sent before you connect, not afterwards. Disconnecting revokes the token; the desktop half is one background thread that simply stops, and every failure it ever has is logged and swallowed rather than surfacing as an error in a product you are using locally.

Why Vercel

Cost, not taste. The alternative on the same account already bills monthly; this one has no contract and no recorded cost. For a mailbox that holds a summary and hashes, a free path is adequate, and choosing a paid one would have been a recurring bill for nothing.

What an update or an uninstall can touch

User data lives in %APPDATA%\dev.jarvis.desktop — entirely outside the installation directory. An update replaces program files and cannot touch projects, sessions or history. An uninstall removes the program and preserves the data.

Schema changes are forward-only and additive, and a database written by a newer build is refused rather than opened — so rolling back a version cannot quietly corrupt the history it does not understand. See Distribution and updates.
