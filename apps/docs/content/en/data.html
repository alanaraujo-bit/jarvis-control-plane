Every path this product writes to, what each one holds, and what an update or an uninstall does to it. Nothing here is hidden and nothing is a proprietary format you cannot inspect.

The one directory that matters

%APPDATA%\dev.jarvis.desktop\

Which on a normal Windows install is C:\Users\<you>\AppData\Roaming\dev.jarvis.desktop\. Everything below is inside it.

It is outside the installation directory, on purpose

An update replaces program files and cannot touch this. An uninstall removes the program and preserves it. Reinstalling picks up exactly where you left off. If you want it gone, deleting this folder is the way — nothing else is holding your data.

What is in it

dev.jarvis.desktop\
  jarvis.db              SQLite, WAL mode — the database
  jarvis.db-wal          write-ahead log
  jarvis.db-shm          shared memory index

  sessions\              one directory per session, ever
    <session-uuid>\
      stream.log         the append-only frame log
      index.bin          sparse offset index, every 256 frames
      guardrail-policy.json   the resolved rules this session started with
      guardrail-settings.json the hook configuration handed to the provider

  accounts\              one provider configuration directory per account
    claude-code\
      <account-uuid>\   this is CLAUDE_CONFIG_DIR for that account

  models\                the local speech model, if you downloaded it

The database

SQLite in WAL mode. It holds metadata, the structured events worth querying, and the full-text search index — but not raw terminal bytes, which is the split the session log exists to make.

Schema changes are forward-only

Migrations are additive and never destructive, and a database written by a newer build is refused rather than opened. Rolling back a version cannot quietly corrupt history that the older build does not understand.

Session logs, and what they cost

One directory per session, forever, unless you delete it. stream.log is the append-only frame log — raw terminal bytes and structured events, in one order. index.bin is a sparse offset index with one checkpoint every 256 frames.

These are the bulk of the storage. History states the total in its header, and per-session sizes on each row, so that deleting is a decision you can make with a number in front of you. No retention policy exists — deleting somebody's history on a schedule is not a decision to make on their behalf.

Account directories

An account is a provider configuration directory. Registering one creates a directory here and points the provider at it with CLAUDE_CONFIG_DIR or CODEX_HOME.

Your existing sign-in is never copied or rewritten

The account already signed in on this machine is adopted and continues to live wherever it already lives — ~/.claude or ~/.codex. Only accounts you add here get a directory here. J.A.R.V.I.S. never opens a credential file; it asks the provider who a directory is signed in as.

Two files written per session, elsewhere from your repository

guardrail-policy.json is the resolved rule set the session started with, plus whether anybody is attended. The guard process reads it, and it is a snapshot on purpose: changing a rule mid-session should not change what a running agent was told.

The Brain brief is written beside these, and passed by path. This is why nothing this product generates ever appears in your git status.

What is not here

Your code
Projects are folders on your disk, opened in place. Nothing is copied.
Your Git history
Read by running the git binary you already have.
Your credentials
Read by the providers, from their own configuration directories.
Anything in the cloud
Unless you paired a phone, and then only a summary of what needs a person. See Local-first.

Backing it up

Copy the whole dev.jarvis.desktop folder while the app is closed. It is a SQLite database and a tree of ordinary files; there is nothing else to capture and no export format to learn.

One file outside all of this, for people building from source

The updater's private minisign key lives in .keys/ in the repository and is gitignored. It must never be committed, and losing it means no existing installation can ever be updated again. Back it up somewhere that is not this machine.
