You had a long session with an agent last week. It knew things — the shape of the problem, what you had already ruled out, the file that turned out to matter. Then you closed the tab.

It is still there.

  1. Find it

    Two ways, and they suit different memories:

    • History if you remember roughly when. Sessions are grouped by day and filterable by range, provider and project. Claude Code names its own sessions, so many of them have a real title.
    • Global Search (CtrlShiftF) if you remember a phrase. It searches what was actually said inside every session you have ever run, and shows the line it matched on.
  2. Read it first

    A row opens a preview: the conversation, read-only. Turns, tool calls, token counts. Nothing is started and nothing is attached — this is a projection of the log, and the log never went anywhere.

    Read enough to remember where you were. That is usually the whole point of coming back.

  3. Continue it

    The preview offers the way back into a terminal:

    • If the session is still live, you rejoin it.
    • If it finished, a new agent is started and handed the old conversation, in a tab named after it.
Verified by planting a fact

A fact was planted in a session, the session was closed, then continued, then asked about the fact. The answer came back: "Amber."

When the offer is not there

Both CLIs resume by opposite mechanisms, and only one of them can be followed afterwards. So the capability model states which, and where continuing cannot work, the offer is absent with a reason rather than present and quietly broken.

ProviderHow it resumesWhat that means here
Claude Code Fork — --resume <id> --fork-session honours our own session id and writes a new transcript named for it. The continuation is a session we can follow from the start.
Codex AppendInPlace — codex resume appends to the rollout it was given rather than creating one. A different shape, and the interface says so rather than pretending they are the same.
If the project folder moved

Continuing into a folder that no longer exists is refused. This was found by doing exactly that and watching a real agent open in the user's home directory instead — which is worse than an error, because the agent then works confidently on the wrong files. The refusal covers every launch into a moved project, not just this path.

Continuing after an account switch

A resume cannot cross configuration directories, so a session that moved to a different account cannot be resumed with --resume at all. Continuity is carried by the Brain brief instead: the new session starts knowing what the project knows, which is the part that actually mattered.

Deleting one instead

If what you want is for it to be gone: History deletes rows, full-text index entries and the log directory, and tells you how many bytes it freed. A live session is refused rather than half-deleted.

No retention policy exists, deliberately. The surface says what the logs cost so that deleting is a decision you can make, rather than one made on your behalf about your own history.
