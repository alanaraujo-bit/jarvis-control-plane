What you need

Windows 11
Or Windows 10 with WebView2, which is present on any machine that has been updated in recent years. Windows is the only platform shipping today.
An agent CLI you already use
Claude Code (claude) or Codex (codex), on your PATH, already signed in. J.A.R.V.I.S. does not install them and does not replace their sign-in.
Git
The git binary. Project detection, Review, worktrees and commit history all ask Git rather than reimplementing it.

Node and pnpm are detected and reported if present, but they are not required to run the app — only to build it from source.

Running the installer

  1. Run the installer Install mode is per-user. There is no administrator prompt, and nothing is written outside your own profile.
  2. Windows will warn you about an unknown publisher This is expected and it is honest. The binaries are not signed with an Authenticode certificate yet — see below. Choose More info → Run anyway if you trust where you got the installer from.
  3. Pick a language The installer detects your OS language and offers English and Portuguese (Brazil), matching the application's own locales.
  4. Launch it The window waits for the first-run check before it appears, so you never see the wrong screen flash past. A first install shows a welcome screen once; after that it opens straight into Mission Control.

Install footprint is 7.3 MB, measured on the real installer rather than estimated. Monaco adds 1.04 MB of that and is loaded on demand rather than at startup.

The SmartScreen warning, explained properly

Two separate signing concerns get confused constantly, so here they are apart:

The Authenticode certificate stops Windows warning about an unknown publisher. It requires a purchase, it has not been bought, and that is a tracked blocker. Nothing technical is missing — the build pipeline already has the shape for it.

The minisign keypair proves an update actually came from us. It exists, it works today, and every downloaded update is verified against a public key compiled into the binary before anything is installed. An update that fails verification is refused rather than applied.

So: updates are cryptographically verified even though the installer is unsigned. Those are genuinely different guarantees.

First run

The welcome screen reuses the same environment scan the product uses everywhere and the same folder picker — there is no bespoke onboarding flow to get out of sync with the real thing. Opening a folder from it lands you inside that project's workspace.

It is gated on a stored flag and shown once per install. If that check ever fails, it defaults to already seen: a broken check should not be able to leave the window hidden.

Check the environment scan

Settings → Environment lists what was found: Git, Node, pnpm, Claude Code, Codex, GitHub CLI, with versions. A provider that is not on your PATH is not offered when you start a session, and this page is where you find out why.

Updating

The updater checks an endpoint, downloads in the background, and verifies the download against the compiled-in public key before installing. Your data is untouched by this: it lives in %APPDATA%\dev.jarvis.desktop, entirely outside the installation directory.

Update checks currently fail, honestly

The update endpoint points at a release location that is not yet published, so Check for updates reports a failure rather than pretending to be up to date. That is a tracked blocker about where to publish, not a bug in the updater.

Uninstalling

Uninstall removes the program and preserves your data — projects, sessions, history, missions and settings all stay. Reinstalling picks up exactly where you left off. If you genuinely want it all gone, delete %APPDATA%\dev.jarvis.desktop yourself; see Where your data lives.

Building it from source

Node 22+, pnpm, and a Rust toolchain with the MSVC build tools.

pnpm install
pnpm dev          # run the desktop app against Vite
pnpm tauri build  # produce the Windows installer

The Rust tests, including ones that drive a real PTY and a real Git repository:

cd apps/desktop/src-tauri
cargo test
cargo test -- --ignored   # also parses every Claude Code transcript on this machine
Close the installed app first

The product enforces a single instance so that exactly one process owns the database and the session logs. If the installed copy is running, pnpm dev will be swallowed silently rather than opening a second window.
