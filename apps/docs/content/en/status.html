Everything below is built and has been driven in a real build against real agents on a real machine — not merely compiled and not merely unit-tested. Where a claim rests on something weaker than that, it says so.

The rule this list is kept to

A milestone ships finished, not scaffolded. Something deliberately absent is listed as absent rather than stubbed out behind a disabled button. A stub is a promise the interface makes and the product cannot keep.

Foundation and the core

Application shell and design system
Custom titlebar, rail, status bar, command palette with subsequence ranking. Dark and light authored independently, both first-class. Reduce-motion respected. i18n wired from the first string, English and Portuguese.
The session event log
Append-only frame codec, sparse index, crash recovery from a torn trailing frame, bounded two-pass replay that never buffers a whole session. SQLite with forward-only migrations. 28 tests, including one against a real Git repository. Read more

The terminal, finished

PTY host, resize, lifecycle, Windows job objects so no agent process outlives the app, single-writer session runtime, raw-byte IPC coalesced at 16ms, xterm.js with per-theme palettes and tabs. Plus three things each verified in a real build:

  • Split panes and layout presets — up to four terminals, three layouts. Verified with two panes both keeping their scrollbacks, a command typed into each reaching its own shell, all three layouts, a third terminal opened mid-split, and closing panes and sessions.
  • Scrollback search — and it took four fixes the test suite could not see, the worst being Ctrl+F falling through to WebView2's own find-in-page.
  • Image paste — verified end to end with a real image on the real clipboard: a genuine PNG on disk, the quoted path typed and left unsubmitted, the preview showing the actual picture, and git status in the project still clean.

Missions, guardrails and unattended runs

The mission model and its seven states, evidence and verification by running real checks, completion refused without evidence and revoked when evidence stops holding, withdrawal recorded with a reason, autonomy profiles inherited down a chain, Mission Control with sections that vanish when empty, missions linked to the agents working on them, and the autopilot.

Guardrails: nine operation classes, a tokenising classifier that respects quoting, policy resolved project → global → default, and enforcement differing by provider with the capability model saying so.

Verified in the installed app, and against a real agent

A mission was created, refused completion, verified, completed — then the artifact was deleted and the completion was revoked.

A policy was set in Settings, a mission whose criterion was npm publish had the check held rather than run, the approval was answered, and the mission left Waiting. Separately, against real Claude Code 2.1.240: a force push was refused before it executed, and under Unattended an rm -rf was stopped with the directory still there afterwards.

Knowledge

Activity, Analytics with human leverage measured from real interaction, Project Brain, project history, notes, and Global Search across knowledge, notes, missions, activity and conversation content.

The Brain, verified end to end

Four facts were written into a scratch project's Brain, Claude Code was started from the app and asked what it knew without reading files. It answered with all four, grouped under the brief's own headings, in a folder it had never seen — and said plainly it had no other context. The brief file was 484 bytes in our own data directory, matching the size the panel reported, and git status in the project was empty.

An agent also writes to its own Brain, once, at the end of an unattended run. The real one it produced is quoted on Project memory.

Preview, onboarding and settings

Preview reads the dev server's URL from the session's own output, enforces loopback in the command and not just the scanner, and opens in a separate window rather than an iframe. Verified against a real dev server, with the LAN address silently excluded and Reload showing a change made on disk.

Onboarding shows once per install and defaults to already seen if its check fails, so a broken check cannot leave the window hidden. Settings is eight sections as destinations, verified in the real build at four widths in both themes and both languages — with control alignment checked by sampling pixels rather than by eye.

Accounts, quota and history

Accounts as configuration directories, the quota model, live official readings from both CLIs on their own supported protocols, automatic switching, twin detection keyed on email, and status-bar chips.

Session History: every session titled, grouped, keyset-paginated, searchable by what was said inside, renameable, deletable — and continuable, verified by planting a fact, closing the session, continuing it and asking. The answer came back: "Amber."

Notifications and the Notebook

Five notification sources with two confidences, a detector built from four recordings of real CLIs and keyed on a shape rather than on wording, a bell, a centre, in-app toasts, Windows toasts, and three switches with a test button that fires the real path.

Verified against a real Claude Code 2.1.241 agent: its folder-trust question read off its own terminal and shown as Observed; its reply shown as Official; nothing raised at all while that session was on screen; and with the window minimised, Windows showed the agent's own reply from the installed build.

The Notebook: folders, notes, autosave, and send to agent — verified with a prompt typed, autosaved, closed, reopened, and sent into a live Claude Code, which showed [Pasted text #1 +5 lines] and left it in the prompt.

Voice

Local dictation with whisper.cpp, primed with the project's own vocabulary, with real-time streaming captions. Tested with a real microphone once — which surfaced two real bugs, both fixed and proven. One ear-test pass is still owed.

Distribution

NSIS installer with product identity, per-user install, updater with minisign verification, single-instance enforcement, silent upgrade path, and an uninstall that preserves user data. Verified on the development machine: installed, launched, upgraded, uninstalled and reinstalled. Install footprint 7.3 MB.
