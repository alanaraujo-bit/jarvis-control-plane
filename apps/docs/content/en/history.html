Every session this machine has ever run: titled, grouped by when it happened, searchable by what was said inside it, and openable again.

Two facts made this a gap

sessions.title had existed since the first migration and nothing had ever written to it, so every session in the database was untitled. And the query that feeds the terminal tabs filters on sessions that have not ended — correct for tabs, and it meant a finished session was unreachable from anywhere in the product except by stumbling on one of its own sentences in search.

Where a title comes from

Precedence is user > provider > derived, enforced in SQL rather than in whichever screen happens to be rendering.

SourceHow
YouRename it inline. Always wins.
The providerClaude Code writes its own ai-title line, and nobody was reading it — present in 89 of the 124 transcripts on the machine this was built against. It is lifted before the noise filter that correctly drops it for Conversation.
DerivedComputed from what was said. Codex states no title at all, so its sessions land here — a real capability difference, with a test that fails if the two providers ever describe themselves identically.

Every older session was backfilled off the startup path, from the search index rather than by re-walking the logs, with the ordering against the search backfill made safe rather than assumed.

Searching what was actually said

The search box searches names and everything said inside, through the same full-text index Global Search uses. A title match sorts above a body match, and a body match shows you the line it matched on.

This is the part the reference this was modelled on cannot do at all.

Continuing a session

A row opens a preview — the conversation, read-only — and the preview offers the way back into a terminal:

  • A live session is rejoined.
  • A finished one is continued by a new agent handed the old conversation, in a tab named after it.

Both CLIs resume by opposite mechanisms and only one of them can be followed afterwards, so the capability model says which — and where it cannot work, the offer is absent with a reason rather than present and broken.

Verified by planting a fact

A fact was planted in a session, the session was closed, then continued, then asked about the fact. The answer came back: "Amber."

A session starts where it says it starts

Found by continuing a session into a folder that had been deleted, and watching a real agent open in the user's home directory instead. That is worse than an error — the agent then works happily on the wrong files. It is refused now, and the refusal covers every launch into a moved project, not just this one path.

Deleting really deletes

Rows, full-text index entries, and the session's log directory — and it tells you how many bytes it freed. A live session is refused rather than half-deleted.

Storage is made visible, not managed

No retention policy was invented

Deciding that sessions older than N days should be deleted is a decision about somebody else's history, and it is not one to make casually on their behalf. So the surface simply says what the logs cost — total sessions, total megabytes, size per session — which turns it into a decision somebody can make.

Two bugs the looking found

  • Every row was forty pixels too tall, because a four-item grid had three columns and the fourth wrapped onto an invisible second row.
  • Clicking a row for an archived project did nothing at all — a silent fall-through that turned out to have been in Global Search since it was built.
One thing deliberately not built
