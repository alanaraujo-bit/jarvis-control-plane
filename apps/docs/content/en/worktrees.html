A Git worktree is a second checkout of the same repository, on its own branch, in its own folder. It is the cleanest way to let an agent work on something without touching what you have open.

A worktree is a project

The decision this page is built on

Creating a worktree creates a project. Opening it opens it everywhere: Review inside it compares against that worktree's branch, Files browses that checkout, sessions start in that directory, and it has its own Brain.

There is no worktree-specific code in the file, editor, Review or Git surfaces. That absence is the evidence the decision had the right shape.

Branch names become folder names, safely

A branch called agent/login-form would become a nested directory if the name were used literally. The slash becomes a dash: agent-login-form. Verified by creating exactly that branch and confirming a single flat folder rather than a directory tree.

Removing one asks twice, for two different reasons

This is worth understanding because it looks like a duplicated confirmation and is not.

  1. Git refuses, because there is uncommitted work

    That is information, and it deserves a plain answer: remove it anyway, or don't. Nothing about guardrails is involved yet.

  2. The forced removal is a guarded operation

    Only now is fs.recursive-delete in play, and only now are the guardrail choices offered.

--force is never passed speculatively. The first attempt is the honest one, and the forced attempt only happens because you said so.

Removing a worktree archives its project row rather than deleting it — the sessions that ran there, and their history, are still yours.

Why this matters for agents

An agent working in a worktree cannot break the checkout you are reading, cannot leave your working tree dirty, and cannot fight you over a file. Combined with Unattended, it is the setup where leaving a run going is genuinely low-risk.

One trap, and it is handled

A worktree is always a brand-new folder, and Claude Code asks whether you trust a folder the first time it opens one. An unattended run started in a fresh worktree would therefore hang forever on a question nobody is present to answer. Starting is refused instead, with the reason — see Autonomy.

Verified in the installed app

A worktree was created for agent/login-form, the slash became a dash rather than a nested directory, it was opened as a project and its own diff was read in Review. Then it was removed — first refused by Git for having work in it, then held by the guardrail, then done, with its project row archived. Both themes, both languages.
