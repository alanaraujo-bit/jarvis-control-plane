Two overlays that look similar and do different jobs. One runs commands. The other finds things you or an agent wrote, across every project you have ever opened.

The command palette — CtrlK

Every rail destination, every settings section by name, and every action the current context offers. Type mc and get Mission Control.

How the ranking works

Subsequence matching, with contiguous runs and word-start matches scoring higher, and shorter titles winning a tie because the more specific command is the one you meant.

for each character of the query:
  find it in the haystack, at or after the last position
  no match anywhere → this command is out
  score += 1
        + 2  for each step of an unbroken run
        + 3  if it lands at the start of a word
then subtract a hundredth of the title's length

Filtering and ranking are one pass: no match and a bad score are the same answer, so the list never has to be walked twice.

The documentation you are reading uses the same scorer

This site's search is a port of that function, unchanged. It is the same interaction in the same product, so typing mc should behave the same way in both places. Press CtrlK here and try it.

Global Search — CtrlShiftF

Five kinds of thing, across every project, always:

Knowledge
Anything in any project's Brain.
Notes
Project notes. Not notebook notes yet — see below.
Missions
Titles, intents and criteria.
Activity
Translated and timestamped, so you can search for a thing that happened.
Conversations
What was actually said, in any session, ever. This is the one nothing else can do.

Why it is never scoped to the open project

The question people ask is where did I see that? Scoping to whichever project happens to be open would silently hide the answer exactly when the answer lives somewhere else.

Opening a session that no longer exists

Global Search is the first thing in the product that can open a session's conversation after the session ended and its tab was closed. That tab is never started and never closed on the backend — nothing was ever attached to it, so there is nothing to detach. See The session event log.

Sessions recorded before search existed

A one-time backfill walks every session log once, off the startup path, one session per transaction — a background task with a bookmark rather than a migration, so it is resumable and idempotent across a crash halfway through.

Verified twice over, and the second one is the interesting one

The walk itself was verified against the machine's real recorded sessions: 55 rows out of 10 real logs, and a Portuguese word from a real Claude Code run came back attributed to the session it was said in.

Then the wiring was verified separately against a real launch, because two earlier bugs in this codebase were both "the code was right and the wiring never ran". The log line confirming the backfill finished is now unconditional for exactly that reason: a background task that is silent in its steady state cannot be told apart from one that never started.

How the index is built

A standalone FTS5 index, not an external-content one. The session events table is WITHOUT ROWID with a composite key, which external-content mode cannot key against.

Knowledge, notes, missions and activity stay on plain LIKE — they are small tables, and it is the same choice the activity list already makes. An index is not free, and one that indexes a hundred rows is a cost with no benefit.

The table this was built on had no writer

session_events had existed since the first migration and nothing had ever written to it. The project's own notes claimed it "exists exactly for this"; that claim was checked before anything was built on it, and found false. It was extended additively rather than recreated, and wired into the transcript tailer that already mirrors usage and file changes.

Two shortcuts, resolved before anything else

Both CtrlK and CtrlShiftF are handled in the capture phase, because the terminal and Monaco both have their own ideas about those keys. A shortcut the interface advertises has to be resolved before any widget gets an opinion about it. See Keyboard shortcuts for what that costs.
