Most products document what they do. This page documents what they do not, because a feature that is absent and a feature that is broken look identical from the outside — and only one of them is worth waiting for.

Absent rather than stubbed

Nothing here exists as a disabled button, a greyed-out menu item or a coming soon panel. A stub is a promise the interface makes that the product cannot keep, and it costs you the time it takes to find out.

Things that will not be built

A Web tab in History
The reference this surface was modelled on has one — it lists Claude's cloud sessions. This product is local-first and does not have them. The tab is absent rather than empty, because an empty tab implies the sessions exist and we failed to fetch them.
Language intelligence in the editor
Monaco's own TypeScript, CSS, HTML and JSON workers are excluded on purpose: without project context they are confidently wrong, and diagnostics you learn to ignore are worse than no diagnostics. Real ones arrive with a language server, and the architecture already leaves room for the client.
Guardrails over your own typing
They govern agents. A command you type in a terminal runs. A tool that second-guesses its owner gets switched off within a week, and then it protects nothing.
A retention policy for session logs
Deleting somebody's history on a schedule is not a decision to make on their behalf. History states what the logs cost instead, which turns it into a decision they can make.

Things that are genuinely not there yet

Starting a mission from your phone

Declined rather than overlooked. Starting one needs the same checks the desktop makes — including the untrusted-folder refusal — and doing those correctly from a phone is its own piece of work rather than a button.

Push notifications to a phone

Its own scope, and it needs a developer account. The relay snapshot already carries what needs a person; delivering it as a push is the same question answered on a different screen.

Global Search does not find notebook notes

It already finds project notes, so a prompt library the global search cannot see reads as a broken search rather than as a boundary. Deferred deliberately, not missed: it needs a new search kind threaded through the shared protocol, the group ordering, the subtitles and both language catalogues — and a navigation special case, because opening a result opens a project workspace and a notebook note has no project to open. A protocol change deserves its own pass.

The Preview surface's cross-platform half

Windows only, like everything else. Nothing in the architecture is Windows-specific, but the PTY host, the job-object containment, the toast integration and the installer all are — and none has been built or verified elsewhere. See Distribution.

Things built but not fully verified

These are the honest ones. They exist, their logic is tested, and something about them has not been looked at or listened to.

The phone web app has never been seen on a phone

Its logic is tested and its transport is proven end to end against real infrastructure — after pairing, the desktop published on its own and the mailbox came back carrying the real machine's hostname with nobody driving it.

But it has never been looked at on a phone-sized viewport. How it behaves is verified; how it looks is not. That is why that milestone is marked in progress rather than complete.

Nobody has heard the notification sound

It synthesises two sine tones through the Web Audio API — quiet by construction, with an exponential envelope so it cannot click — and it is on by default. Every other notification channel was verified by looking. This one cannot be, and it has not been listened to.

Two questions decide it: is it audible from another room, and is it annoying at the desk? If it is either wrong, the switch is already in Settings.

Voice is owed one live pass by ear

Dictation has been driven end to end for real once with a real headset, and the streaming path has been driven live through the installed app using a synthetic-audio bypass — the development machine has no microphone attached.

What has not happened is a single pass confirming, by ear, all of: the start and finish sound cues, the two bug fixes that pass produced, and the live captions, together, on a real microphone. It shares this debt with the notification sound and should be judged in the same sitting.

The account-rotation end-to-end run is set up and unrun

Every part of it is built and exercised: the registry, the configuration-directory plumbing, the quota model, the panel, the manual and automatic switch, and the Brain relay across a switch. What has not been executed is the external one — an account genuinely exhausting, work moving to a separately authenticated account, and the agent carrying on.

It costs real tokens on real accounts and writes real sessions, so it is scheduled rather than slipped in.

One thing that is probably, not certainly, covered

The notification detector reads a question off the terminal for Claude Code and Codex, and its evidence is four real captures from those two CLIs. The invariant it keys on is a shape — a numbered choice list with exactly one cursor glyph — rather than any wording, so a third agent CLI would very likely work.

But it has not been recorded, and probably is the honest word. The capture harness that produced those four recordings is part of the codebase precisely so that a third one can be added properly rather than assumed.
