The loop is ask → modify → run → see → inspect → fix. Every step but see already lived in this product: an agent edits files, runs a server in a real terminal, and the diff is in Review. Preview is the missing step.

Nothing to configure, no port to guess

Where the address comes from

The dev server's URL is read from the session's own output. When an agent runs npm run dev, the address it printed is already in the log this product keeps. There is no port setting, no guessing, and no scanning.

This is also the one thing a browser cannot know: which session started this server. Preview follows the active session, so switching between two agents running two servers shows you the right one without asking.

If a session is serving more than one thing, you are offered the choice rather than having one picked for you.

Detection is automatic; opening is a click

Nothing opens by itself. The address is detected as soon as it is printed, and Preview waits for you. An agent restarting a dev server should not make a window appear over what you were reading.

Loopback only, and that is a security boundary

Preview renders inside our own window. If it would point at any host because a string appeared in terminal output, then any program a session runs could choose what this product displays.

So the address must be loopback, and this is enforced in the command that opens it — not only in the scanner that found it. Both use the same check, and it parses the URL properly with a URL library rather than matching a prefix.

✓ allowed  http://localhost:4173
✓ allowed  http://127.0.0.1:5173

✗ refused  http://127.0.0.1.evil.com
✗ refused  http://localhost.evil.com
            both of these sail through a prefix check
✗ refused  http://192.168.1.40:4173
            a LAN address is not loopback, even though it is yours

A separate window, not an iframe

The iframe was the obvious first choice and it does not work. The application's content security policy is default-src 'self'. Widening it would put a dev server's page in a context adjacent to the surface that can invoke every command in this product — a real privilege escalation traded for a layout convenience.

A separate webview has its own, empty capability set. So Preview opens beside the app rather than inside it.

Reload

The did that actually change anything? button, for a dev server without hot reload. It exists because the alternative is leaving the app, and leaving the app is where the session context gets lost.

Verified end to end against a real dev server

npx serve printed both a Local and a Network address. Preview offered localhost:4173 and silently excluded the LAN address. Open rendered the real page in its own window; the file was then edited on disk and Reload showed the change — the whole loop, closed. Both themes, both languages, plus the empty state and the follow-the-active-session behaviour.
