Every setting, its default, its bounds, and what actually happens the moment you change it. Values are read from the source rather than from a screenshot.

Two rules that apply to all of them

Unset is no row. A setting you have never touched has no database row at all, which is what lets a default change reach you.

Bounds are enforced in the core, in both directions. Out of range on the way in is refused, so a stored value is always one somebody could have chosen. Out of range on the way out is clamped, so an older build's row cannot produce an unusable terminal or a zero budget that fails every run before it starts. A value that will not parse reads as unset rather than failing the screen.

Autonomy

SettingValuesDefaultNotes
Default profile Guided · Autonomous · Unattended Autonomous The bottom of the chain. Resolved mission → project → global.
Turn budget 4 – 100 turns 24 A run keeps the budget it started with. Re-reading it each turn would let a change here move the finish line under a run already going.
Why 4 and 100 specifically

Below 4, an unattended run cannot finish anything real and every mission would end in Failed. Above 100, run until done stops being a budget at all — which is exactly what the rule against consuming resources indefinitely exists to prevent. These are product decisions, not arbitrary numbers.

Guardrails

Nine rows, one per operation the core reports, each Always ask · Allow · Never allow, defaulting to Always ask.

The list is generated from what the core reports, so it can grow without this screen being touched. See Guardrails for the nine and what each matches.

Under Unattended, Always ask becomes a refusal

Nobody is there to answer. Rather than park the agent on a prompt that will never be answered, the guard refuses and the mission goes to Waiting with a reason.

Phone

Pairing state, a six-character code (single use, five minutes, attempts counted), and a statement of what is sent — before you connect. Disconnecting revokes the token, not just the local pairing. See Pair your phone.

Environment

Read-only. What was found on this machine — Git, Node, pnpm, Claude Code, Codex, GitHub CLI — with versions, and a Rescan button. A provider that is not on your PATH is not offered when you start a session, and this is where you find out why.

Updates

Your current version, and a check against the update endpoint. The download is verified against a minisign public key compiled into the binary before anything is installed; an update that fails verification is refused rather than applied.

Update checks currently report a failure honestly, because the release location is not yet published. See Known blockers.

Project settings

A project's own Settings area hosts the project-scoped autonomy and guardrail controls. They are literally the same components as the global ones, given a project id — which is why the two can never drift apart.
