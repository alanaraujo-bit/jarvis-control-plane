Be told when an agent stops working — because it finished, or because it needs a decision — with a preview of what it wants.

The rule the whole thing turns on

Notify only about what you are not already looking at

Watching means the window has focus and that session is on screen. Both, together.

And a suppressed notification is dropped entirely, not stored and marked read. That is what makes the centre a list of what you missed rather than a log of everything that ever happened.

This is decided in the core, in one place, and tested — not left to each surface to work out for itself.

Five sources, two confidences

SourceConfidenceBecause
A turn finishedOfficialThe provider stated it.
A guardrail decidedOfficialWe decided it.
A mission completedOfficialVerification ran.
A run stoppedOfficialThe autopilot stopped it, with a reason.
A question on the terminalObservedNothing stated it. It was read off the screen.

Why the fifth one has to exist

Claude Code asking whether it may write a file is stated nowhere. The guardrail hook returns early for anything that is not a classified shell command, and the transcript records the answer rather than the question. The only place that question exists is on the terminal.

So it is read from there — and labelled Read from the terminal, so you always know which kind of claim you are looking at. See Official and Observed.

How it is detected without guessing at wording

The detector was built from four recordings of real agent CLIs, and it keys on the one invariant that survives all four: a numbered choice list with exactly one cursor glyph. Never on the words. Wording changes with every release; the shape of a prompt does not.

A match is only trusted as a conjunction: the shape holds, and the terminal has been quiet, and nothing has been typed since. Any one of those alone produces false positives.

A third agent CLI is probably, not certainly, covered

The evidence is four real captures from two CLIs. The invariant is a shape rather than a sentence, so a third CLI would likely work — but it has not been recorded, and saying probably is the honest word.

Escape sequences, and why a plain strip breaks this

These TUIs emit cursor-forward escapes where a person sees a space. A conventional strip_ansi therefore turns

Do you want to create hello.txt?

into

Doyouwanttocreatehello.txt?

So the preview goes through a renderer that understands cursor movement rather than a filter that deletes escape codes.

Where a notification appears

  • A bell in the titlebar, with a count.
  • A centre under it — the list of what you missed.
  • An in-app toast when the window is in front of you.
  • A Windows toast when the window is behind something else, plus a taskbar flash and a short sound.

What a Windows toast can and cannot do, measured

Fired from the installed build before the interface was written, which is why the interface is shaped correctly:

  • It appears, attributed to us — our own mark and name — on a machine that also carries an unrelated jarvis.exe with its own Start Menu shortcut.
  • It does not appear from a development build, because the plugin only sets the application identity for a packaged binary, and an unpackaged one has no shortcut to be identified by.
  • Clicking it does nothing, and cannot. The notification plugin exposes activation callbacks on mobile only.

So the desktop toast is an alert and the centre is the thing you click. Built the other way round, this would have shipped a toast that looks interactive and is not.

The one that would have shipped broken

isFocused() returns true for a minimised window on Windows

The feed asked it the instant a notification arrived, concluded the person was sitting right there, drew an in-app toast onto a window nobody could see, and never fired the desktop toast — which is the entire point of the feature. Nothing in the interface looked wrong: the notification appeared correctly in the centre.

Caught by asking Windows what it had actually been handed, and finding nothing from the run that had just happened. The fix is not a better call but no call: the surface reads the focus state that was last reported to it, and checks minimised state beside it.

Four more found by running it

  1. The count badge covered the bell — a 13px badge on a 14px icon. Visible only by zooming into a real screenshot.
  2. The toast's close button sat level with the middle of the agent's own question and read as part of the text.
  3. Opening the centre erased the thing it was opened to see. Marking everything read is right, and it also cleared the marker showing which rows were new.
  4. Clicking a notification for an already-open project did nothing, because re-opening the same project is not a remount.

Unattended runs are quieter

A driven session's finished turns are dropped. Under the default budget you would otherwise get twenty notifications while away by choice, then a twenty-first when the run actually stopped — the only one you wanted, at the bottom of a pile.

Its questions are not dropped. A driven agent that stops to ask is the one thing about an unattended run worth interrupting somebody for.

Settings

Three switches in Settings → Notifications — notify at all, also show a system notification, play a sound — and a test button that fires the real path rather than a simulation of it.

The sound has never been heard

It synthesises two sine tones through the Web Audio API — quiet by construction, with an envelope so it cannot click — and it is on by default. Every other channel was verified by looking; this one cannot be, and nobody has listened to it yet. See What is not built.
