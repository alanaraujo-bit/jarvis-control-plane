A notepad you can reach without leaving the terminal, with folders for the prompts and ideas you have been hoarding. The part that matters is not the notepad — it is the one action a note-taking app cannot do: hand the note to the agent you are watching.

Opening it

CtrlShiftN from anywhere, a button in the titlebar, or the command palette.

The shortcut is resolved in the capture phase, for the same reason CtrlK is: a terminal and Monaco both claim keys before a normal listener ever sees them, and the moment you want your prompt library is the moment a terminal has focus.

Structure: one level, on purpose

Folders
Flat. One level. A prompt library is a list you scan, not a hierarchy you navigate.
Unfiled
A real place, not an absence. A note does not need a folder to exist.
Notes
Title and body, autosaved as you type, with a flush on every exit. Pin, move, duplicate, copy, delete.
Deleting a folder cannot lose your notes

The notes inside it move to Unfiled. This is enforced by the database schema, not by a confirmation dialog: a shape that cannot lose forty prompts beats a dialog somebody clicks through at speed.

Send to agent

The button in the corner sends the note into the terminal you were on. Two rules govern it:

  • It is never submitted. The text arrives in the prompt and stays there. You edit it and press Enter. This is the same rule voice dictation and image paste follow — pressing Enter stays yours.
  • It is refused when the receiving program has not enabled bracketed paste. A plain shell would interpret a multi-line prompt as twenty commands rather than one prompt. So it is refused with a sentence, and nothing is written.

How the text gets there

Through xterm's own paste path rather than a Rust typing command, and that distinction was decided by measurement rather than by preference.

The measurement that decided it

The typing helper that types into a terminal flattens every newline to a space. Sending a multi-paragraph prompt through it would have delivered run-on lines while looking entirely correct on screen. Measured against real Claude Code 2.1.245 instead of assumed: through paste, three lines arrived intact and unsent.

Search

The box at the top searches titles and bodies across every folder.

One gap, known and deferred

Global Search does not find notebook notes yet. It already finds project notes, so a prompt library the global search cannot see reads as a broken search rather than as a boundary. It is deferred deliberately: it needs a new search kind through the shared protocol and both language catalogues, and a navigation special case, because a notebook note has no project to open. See What is not built.

Verified in the real build

A prompt was typed, autosaved, closed, reopened, and sent into a live Claude Code, which showed [Pasted text #1 +5 lines] and left it sitting in the prompt. The same note sent into a plain shell was refused with a sentence and wrote nothing. Both themes, at 1442px and 786px.
