The same session as the Terminal, read as structured turns. Not a second session, not a second store, and not ANSI scraped out of the terminal — a projection of the same log.

What the toggle does, and does not do

Flipping Terminal · Conversation changes which projection is on screen. It does not touch the process. Nothing is restarted, no context is lost, and you can flip back and type mid-turn.

Where the structure comes from

Both CLIs write a structured JSONL transcript to disk while running interactively. That was the question the entire product design turned on, and the answer is yes. Conversation reads that, folded into the same log as the terminal bytes, in one order.

What a turn shows

Messages
User, assistant and system, each attributed. Your side reads You, the agent's side reads Agent.
Tool calls, with their results
Paired rather than listed separately, so a call and what it returned are one thing to read.
Thinking
Where the provider emits it, shown as its own kind rather than mixed into the reply.
Errors
Shown, not swallowed. An agent that failed is more interesting than one that was quiet about failing.
Token usage per turn
Input, output, cache creation and cache read — Official, from the provider's own usage object. Never an estimate dressed as a fact. See Official and Observed.

The turn boundary is stated, never inferred

A quiet terminal does not mean an agent finished. It might be thinking, waiting on a network call, or about to print another thousand lines. So the end of a turn comes from the provider:

  • Claude Code reports stop_reason: "end_turn". "tool_use" means it is still working.
  • Codex emits event_msg/task_complete.

Both are projected as the same thing. This was checked against all 88 transcripts on the development machine: 664 turn boundaries, none of them a tool_use. It matters most for unattended runs, where inferring the end of a turn from silence would make the autopilot interrupt an agent mid-thought.

Reading a finished session

A session that ended still has a conversation, because the log is still there. History and Global Search both open one as a read-only tab. That tab was never started and is never closed on the backend — nothing was ever attached to it, so there is nothing to detach.

The parser, and what it survives

Reading a JSONL file that another process is actively appending to is less simple than it sounds. The tailer handles partial lines, UTF-8 sequences split across two reads, truncation, and CRLF.

It was validated by running over every real transcript on the development machine — 79 files, 49,905 conversation items, 19,582 of them carrying official usage — rather than against synthetic fixtures that only contain the shapes somebody thought of.

A bug this surface's data had, worth knowing

Usage and searchable text were routed by one match. A message carrying both — the ordinary shape of an assistant reply — took the usage arm, so its text was never indexed. Searching for an agent's own reply returned only the question that prompted it. Found by running a real turn and searching for its answer, which is not a thing a unit test would have thought to do.

What is deliberately not translated

The interface around a conversation is translated. The conversation is not. An agent's own words are what it said; rendering them in another language would be presenting words nobody spoke as if they had been. The same rule governs command output stored as mission evidence.
