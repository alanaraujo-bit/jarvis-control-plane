Decide once what an agent may never do. Ten minutes now, and you can leave a run going without having to think about it again.

  1. Open Settings → Guardrails

    Nine rows, one per class of sensitive operation, each with Always ask, Allow and Never allow. Everything starts on Always ask, which is the honest default: the product does not know your risk tolerance.

  2. Set the two that are almost always right

    Read a credential file and Deploy to production are the two most people want on Never allow and never think about again. Neither is something an agent should be doing on your behalf while you are elsewhere.

  3. Think about the destructive three

    Force push, Rewrite history and Throw away uncommitted work. The third is the one that matters most and gets the least attention: it is the only thing on the list that Git keeps no copy of. A force push can be recovered from a reflog; a discarded working tree cannot be recovered from anything.

  4. Override per project where it makes sense

    A project's own Settings area has the same panel. Rules resolve project → global → default, and unset genuinely means unset — so a global change still reaches every project that never expressed an opinion.

    The obvious case: Publish a package set to Never allow globally, and Always ask in the one repository you actually publish from.

  5. Watch one actually work

    Start a Claude Code session in a scratch repository and ask it to force-push. The command is stopped before it runs and you get a decision to make. Answer it, and look at Activity — the decision is recorded there with the operation it classified.

Four things to know before you rely on this

Codex needs one extra step
It has the same hook mechanism, but will not run a hook until you trust it in Codex's own interface. J.A.R.V.I.S. writes the configuration at session start so it is there to be trusted. Until you do, that session is observed, not guarded, and the capability model says so rather than showing you a shield that is not doing anything.
Your own typing is never guarded
Guardrails govern agents. A command you type in a terminal runs. That is deliberate — a tool that second-guesses its owner gets switched off within a week.
Not flagged is not the same as safe
The classifier matches patterns over command text. A command it does not flag failed to match a pattern; it was not proven harmless. Those are different claims and only one of them is true.
It fails open
A missing snapshot or a version it does not understand means it stays silent and the command proceeds. This runs before every tool call in every session, so a guard that failed closed would turn any bug in itself into an agent that cannot work at all, everywhere.

Under Unattended, "ask" refuses

Nobody is there to answer, so a rule set to Always ask becomes a refusal, and the mission moves to Waiting with a reason. Decide before you walk away whether you would rather that operation happen or the run stop — because those are the only two options once you are gone. See Run a mission unattended.

Answering from your phone

If you have paired a phone, a held operation reaches it. Only allow once is available there: the other answers write lasting policy, and a lasting policy decided on a small screen with a thumb is the wrong kind of decision to make quickly. Not approving is a refusal, and the guardrail already refuses by default.

Discarding in Review

Inside Review, discard is guarded and staging is not. Guarding staging would teach you to switch the guardrail off, and then the discard is unguarded too — which is how you end up guarding nothing. The gate names its operation directly rather than classifying a string it just built, and it asks you there rather than creating something to resolve later.
