Every tool that puts a chat next to a terminal has to answer a question it usually ducks: which one is true? If the terminal says one thing and the transcript says another, which do you show, and what happens to the ordering between them?

J.A.R.V.I.S. answers it by refusing the premise. There is one store, one writer and one order. The terminal and the conversation are two ways of reading it.

One log, many projections

Nothing on the right holds state of its own. Close the Conversation tab and reopen it a week later and it is rebuilt from the same frames — which is also why a finished session can be reopened at all.

What a frame is

A frame is a length, a sequence number, a millisecond timestamp, a one-byte kind, and a payload. The kinds are fixed and their numbers are never reused, because logs already written on your disk are decoded with them.

KindByteWhat it holds
PtyOutput1Bytes the process wrote. The terminal's own truth, escape sequences and all.
PtyInput2Bytes sent to the process, so a replay shows what was typed rather than only what came back.
Message10A structured user, assistant or system message, as JSON.
ToolCall11A tool the agent invoked.
ToolResult12What that tool returned.
Usage20A token or rate-limit sample, always carrying its confidence.
FileChange21A file this session created, modified or deleted.
Lifecycle30Started, state changed, resized, exited.
Attachment40An image or file attached to the session.
Approval50A guardrail request and the answer it got.

Terminal size is a frame, and that is not a detail

Output that positions the cursor absolutely renders as garbage when it is replayed into a terminal of a different width. So Resized is a lifecycle frame written at start and on every change: the replay always knows how wide the terminal was at that point in the stream. A session log without it would look correct until the first agent that draws a progress bar.

Why the bytes are not rows

The split

sessions/<id>/stream.log — the frames, append-only, binary.
sessions/<id>/index.bin — a sparse offset index, one checkpoint every 256 frames.
SQLite — metadata, the structured events worth querying, and the search index.

An agent working for three hours produces tens of megabytes of terminal output. Stored as database rows, both the writes and the replay get slow enough to notice, and the database file grows in a way nobody can reason about. Stored as a framed file with a sparse index, appending is one write and seeking is one lookup plus a short scan.

The index is sparse on purpose. One entry per frame would make the index a second copy of the log; one entry every 256 frames keeps it tiny and still bounds a seek.

What happens when the power goes out

A process killed mid-append leaves a partial trailing frame. On open, the log scans forward from the last index checkpoint, finds the last complete frame, and truncates everything after it.

A torn write therefore costs at most one frame. It does not corrupt the session, it does not require a repair tool, and it does not lose the two hours before the crash. There is also a guard against a corrupt length field: a frame claiming more than 64 MB is refused rather than allocated.

One writer, always

The rule that makes the order a fact rather than an agreement: a session has exactly one writer. The session runtime owns the log. Nothing else appends to it — not the transcript follower, not the guardrail process, not the autopilot.

Things that need to contribute hand their contribution over the same way a provider does: by writing to a file that the single writer follows. The guardrail is the clearest case — it runs as a separate process, and it appends its decisions to guardrail-decisions.jsonl, which the session runtime tails and turns into Approval frames.

What this buys you, concretely

Terminal ↔ Conversation, live
Flipping the toggle on a running agent changes which projection is on screen. The process is not touched, nothing is restarted, and no context is lost.
Sessions that outlive their tab
History can open a session that ended months ago as a read-only conversation, because there was never anything to keep alive — only frames to read.
Numbers that are not invented
Analytics folds Usage frames. It never estimates a token count, because it never has to.
Attribution without bookkeeping
Review can say which agent changed a file because FileChange frames already recorded it. It is a join, not an invention.
Search over what was said
Global Search indexes message text from the same stream, which is why it can find a sentence from a session you closed weeks ago.

The bug this design still allowed

Worth knowing, because it shows where the seams are. Global Search once returned only the questions from a conversation and never the replies. Usage and searchable text were being routed by a single match, so a message carrying both — the ordinary shape of an assistant reply — took the usage arm and its text was never indexed.

One log did not prevent it. What one log did was make it a small fix in one place, and make the repair verifiable by running a real turn and searching for its own reply.
