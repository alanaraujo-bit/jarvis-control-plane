You left an agent working and came back. Review answers the only question that matters: what did it actually change?

Git decides what changed

The rule

git status --porcelain=v1 -z for the list. git diff -M HEAD for the hunks. We parse; we never compute a diff ourselves and hope it agrees with your own git.

-M is why a renamed file renders as one changed line rather than as a whole file deleted and a whole file added — verified by renaming a file and reading the result, not assumed from the flag's documentation.

Attribution is a join, not an invention

Review can tell you which agent changed a file. It does not need a separate ledger to do it: the session log already records a FileChange frame for every file a session touched, so the answer is a query against data that was being written anyway.

A file changed by a real Claude Code session shows up at the top of the list, attributed to Claude Code. A file you changed yourself is simply a file that no session claims.

Git write operations

Stage, unstage, discard, restore and commit — all from here, all running real Git.

ActionGuarded?Why
Stage · UnstageNoThey move the index and are reversible.
CommitNoReversible, and Git keeps a copy of everything in it.
Restore a deleted fileNoIt creates; it does not destroy.
Discard changesYes — git.discard-changesThe one thing Git keeps no copy of.

Guarding only the discard is a deliberate choice, and the reasoning generalises: asking about staging would teach you to switch the guardrail off, and then the discard is unguarded too. Guarding everything is how you end up guarding nothing.

The gate names its operation

Review does not build a command string and then feed it to the classifier to find out what it just decided to do. It names the operation directly. It also writes no pending row — you are at the screen, so the question is asked and answered right there rather than becoming something to resolve later.

Every Git spelling was checked before it was written down

Plain git restore restores from the index, so a discard built on it silently keeps staged content — you would press discard, see the working tree change, and still have the staged version sitting there. The discard here goes to HEAD, and that was confirmed on disk by discarding a file carrying both staged and working-tree changes.

Inside a worktree

Review inside a worktree compares against that worktree's own branch. There is no worktree-specific code here at all — a worktree is a project, so it works because everything else already does.

Verified in the installed app

A real Claude Code agent was run in a scratch repository, watched creating a file, and that file appeared at the top of Review attributed to Claude Code. A file was staged and unstaged; a file carrying both staged and working-tree changes was discarded and confirmed on disk to have reached HEAD; a deleted file was restored; three staged files were committed. Then Never allow was set for discard and the next discard was refused with the working tree untouched. Both themes, both languages.
