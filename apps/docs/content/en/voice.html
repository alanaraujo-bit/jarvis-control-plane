Dictation into a running agent. Not a voice-command surface — an input method for a session you are already in, because the thing people actually want is to describe a change out loud instead of typing three paragraphs.

Entirely local

No cloud, no key, no account

whisper.cpp is bundled and spawned as a local process. There is no speech API, nothing to configure, and your audio never leaves the machine. The model is downloaded once through the app's own interface — about 490 MB — and hash-verified before it is used.

Primed with your project's own vocabulary

A generic dictation tool gets the proper nouns wrong, every time, and those are exactly the words that matter in a prompt about your code. So the transcriber is primed with the project's own vocabulary: its file names, its branch.

This was verified rather than assumed — the same recorded sentence, transcribed twice, with and without priming. It fixes precisely the proper nouns the generic pass gets wrong.

Live captions while you speak

A warm transcription server is polled roughly every second, and the result is folded through a commit-and-tail split so that the caption only ever grows and never rewrites a settled word. Words that are committed stay put; the volatile tail breathes.

What actually gets typed is untouched by this: it is still one complete, unstreamed pass when you stop. The captions are for you while you talk; the transcription is for the prompt.

It types, it does not submit

The text lands in the prompt and stays there. You edit it and press Enter. The same rule governs sending a note and pasting an image — pressing Enter is yours, always.

Two bugs a real microphone found

Both of these are invisible to a test suite and obvious within ten seconds of a real headset:

PSReadLine's audible bell
Typing into a PowerShell prompt made it beep. Irritating in a way nobody notices until they hear it, and nobody hears it in CI.
UTF-8 split across chunks
Dictated accents garbled specifically inside Claude Code's own TUI, because a multi-byte character was being split across two writes. Fine in a shell, broken in the one place it mattered.

Both are fixed and proven against real infrastructure.

A process that outlived the app

The streaming server survived a forced kill of the application and kept running. Fixed with the same Windows job-object containment that agent processes already use — nothing this product starts should be able to outlive it.

What is still unverified

One live pass, by ear, is still owed

Voice has been driven end to end for real once with a real headset, and the streaming path has been driven live through the installed app using a synthetic-audio bypass — this machine has no microphone attached. What has not happened is a single pass confirming, by ear, all of: the start/finish sound cues, both bug fixes above, and the live captions together, on a real microphone.

It is recorded as owed rather than quietly assumed. See What is not built.

A missing microphone

Reported honestly rather than hanging. A feature that silently does nothing when the hardware is absent is indistinguishable from a feature that is broken.
