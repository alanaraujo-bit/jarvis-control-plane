Several subscriptions, each with its own window, and work that moves to the next one instead of stopping.

  1. Look at what you already have

    Open Accounts. The account already signed in on this machine is adopted — it is there without you registering anything, because an account is a configuration directory, and yours already exists.

  2. Add another

    Add account creates a new configuration directory and starts the provider's own sign-in. That opens a browser and you complete the OAuth flow.

    This product never sees a password or a token

    Sign-in happens entirely inside the provider's CLI. Afterwards J.A.R.V.I.S. asks the provider who this directory is signed in as and stores the email, organisation and plan — so you can tell four accounts apart on screen. Nothing else is read, and nothing you already had is rewritten.

  3. Check for twins

    If two cards show identical statistics under different names, they are probably one subscription drawn twice — the same email signed in to two directories. The product detects this, keyed on email rather than organisation, and says so on both cards above the dial.

    It does not prevent it. Two directories on one account is legitimate. It just makes sure you are not looking at a lie.

  4. Choose a switching mode
    ModeWhat it doesChoose it when
    OffYou pick, always.You want to know exactly which account each piece of work is on.
    When exhaustedNew work moves once the provider says an account is out.The sensible default. You lose nothing and nothing surprises you.
    Near the limitNew work moves before it runs out.You start long unattended runs and would rather not have one stop halfway.

    Running sessions keep their account. A switch changes where new work starts; it never pulls the configuration directory out from under an agent mid-task.

  5. Read the chips instead of the screen

    Once this is set up, the status bar is where you actually check. Each provider's remaining allowance and reset, permanently visible, so the answer is there when the question comes up — which is when you are about to start something, not when you are on this screen.

Reading a card properly

The dial shows what is left
Not what has been consumed. You are deciding whether to start something.
Two windows, and one of them is binding
A session window and a weekly window are different limits, and either can be the one stopping you. The binding one says this is the limit holding you up and is drawn larger than the one that is not.
A countdown and a wall clock
56m answers "can I wait?". 13:10 answers "should I go to lunch?".
Provenance and age
Every reading says whether it is Official and how old it is. Check now refreshes it. See Official and Observed.

What a live check actually does

It asks the CLI on its own supported protocol — get_usage on Claude Code's control channel, account/rateLimits/read on codex app-server. No HTTP endpoint of ours, no reading your credential files, no token spent, and no transcript written.

Each probe was also run against an empty configuration directory before any of this was built: both read the account in the directory they are pointed at, and both fail by saying so rather than returning the ambient account's numbers under the wrong name. That check is kept as a permanent safety test.

Continuity when work moves

A resume cannot cross configuration directories, so an agent moved to a new account is not resumed — it is started fresh with the Brain brief. The new session knows what the project knows, which is the part that mattered. This is also the reason the Brain is worth filling in properly if you work across several accounts.
