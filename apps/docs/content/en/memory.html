An agent that starts in your project knows nothing about it. Not the port your dev server actually listens on, not the rule that invoices are never edited, not what your team means by tenant. It will read files and infer some of it, badly, every single time.

J.A.R.V.I.S. has three stores for this, and the reason there are three is that they answer three different questions.

Knowledge Facts that stay true about a project. Briefed to every agent that starts here. Notes Your working memory for this project. Never sent anywhere. The Notebook Your prompt library, global. Sent only when you press the button.

One question decides which is which

The rule

Knowledge is briefed; a note is not. That is the whole distinction, and it is structural: the function that composes a brief takes only knowledge, so a note cannot arrive through it even by accident. There is no per-item switch to forget to set.

If you find yourself wondering which one something is, ask whether you would want the next agent to be told it before it reads a line of code. Yes is knowledge. No is a note.

Knowledge, and its four kinds

What this project is
The one-paragraph orientation. Aurora is the billing service: invoices, credit notes and the reconciliation job that runs every night at 02:00 UTC.
How work is done here
Conventions an agent would otherwise violate. An invoice is immutable once issued. Corrections are credit notes, never edits.
Things that will bite you
The non-obvious traps. The dev server listens on 4173, not 3000 — port 3000 on this machine is held by an unrelated service.
What words mean here
Your vocabulary, where it differs from the general one. A tenant here is a billing account, not a user.

Stated and derived are separate tabs

Knowledge you wrote carries who said it. Facts the product derived — the branch, the languages, what changed recently — are recomputed on every read and never stored. They live on their own tab, which makes the confidence rule structural rather than a caption somebody has to notice.

Retiring, not deleting

Knowledge that stops being true is retired: it stops being briefed and the record stays. A fact that was true for six months is part of the project's story even after it stops being true.

How the brief reaches the agent

Out of band, and this matters more than it sounds.

The brief is written beside the guardrail snapshot in J.A.R.V.I.S.'s own data directory and passed to Claude Code with --append-system-prompt-file. Nothing is written into your repository. A context file dropped into a working tree would show up in the Review surface this same product ships, in your git status, and eventually in a commit.

Codex has no equivalent flag on 0.147.0, so it is reported as OpeningMessage — it would have to arrive as the session's first message, visible and costing a turn. The capability model states this rather than handing Codex a file it would never read.

Verified, end to end

Four facts were written into a scratch project's Brain. Claude Code was started from the app and asked what it knew without reading files. It answered with all four, grouped under the brief's own headings, in a folder it had never seen — and said plainly it had no other context without reading the repo. The brief file was 484 bytes in J.A.R.V.I.S.'s own data directory, matching the size the panel reported, and git status in the project was empty.

An agent can write here too

At the end of a successful unattended run — once, and only there — the agent is asked one narrow question: what would still matter next time? Not a summary of the task. It is forbidden from touching anything while answering, because a stray edit at that moment could be why a later re-verification revokes the completion it just earned. And it is given a named way out, NOTHING TO RECORD, which is expected to fire most of the time.

What it writes is marked An agent recorded this, in amber, so you always know which sentences came from a person and which did not.

The real one this produced

A trivial mission ran unattended against a real Claude Code agent in a project whose README stated one non-obvious fact. On completion it answered: GOTCHA: The dev server runs on port 4173, not the conventional 3000, because port 3000 on this machine is already held by an unrelated port scanner — anyone expecting localhost:3000 will find nothing there. That sentence is now in the Brain, and every agent that starts there is told it.

Notes, and promoting one

Notes are yours. Pin them, reorder them, delete them; they are never composed into a brief and never leave your machine. When a note turns out to be a fact the next agent should know, one action promotes it into knowledge — and it leaves the notes list, because it is now a different kind of thing.

Where the Notebook fits

The Notebook is the third store and the odd one out: it is global rather than per-project, it holds prompts rather than facts, and it is the only one you hand over deliberately — one button sends a note into the agent you are watching, unsent, so you can still edit it before it goes.

Everything else about memory is about what an agent is told automatically. The Notebook is about what you say to it on purpose.

One gap, known

Global Search finds project notes but does not yet find notebook notes. It is deferred rather than missed — it needs a new search kind through the protocol and both catalogues, plus a navigation special case, because a notebook note has no project to open. See What is not built.
