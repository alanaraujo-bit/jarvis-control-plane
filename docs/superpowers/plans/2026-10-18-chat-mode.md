# Chat Mode (M29) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A second way to work with Claude Code and Codex — a clean chat screen driven by each CLI's structured protocol — chosen per session and as a preference, with the terminal still the default.

**Architecture:** A chat session is a `LiveSession` whose process is a piped child (`claude -p … stream-json` / `codex app-server`) instead of a PTY. The provider's transcript keeps feeding the same append-only log through the existing tailer (durable conversation); a per-provider driver turns the protocol's stdout into live UI events (streaming text, permission and question requests, busy state, model/effort) sent over a Tauri `Channel`. Requests, resolutions and setting changes are logged as `Approval`/`Lifecycle` frames.

**Tech Stack:** Rust (Tauri 2, rusqlite, serde_json, std::process), React 19 + TypeScript, zustand, lucide-react, `@jarvis/i18n`, `node --test` for pure TS modules.

**Spec:** `docs/superpowers/specs/2026-10-18-chat-mode-design.md`

## Global Constraints

- A session is one append-only log; the chat keeps no conversation store of its own. Durable conversation = `session_conversation` (log projection).
- Chat exists for `claude-code` and `codex` only; read from `ProviderCapabilities::chat`, never matched on ids in the launcher/UI.
- Claude chat launch: `claude -p --input-format stream-json --output-format stream-json --verbose --include-partial-messages --permission-prompt-tool stdio --session-id <id>` + optional `--resume <prev> --fork-session`, `--settings <guardrail-settings.json>`, `--append-system-prompt-file <project-brief.md>`. **No** `--model`, `--effort`, `--permission-mode`.
- Codex chat launch: `codex app-server`; `thread/start {cwd}` with no `approvalPolicy`/`sandbox`.
- "Always allow in this conversation": Claude = suggestions with `destination` rewritten to `"session"`; Codex = `acceptForSession`. Nothing is ever written into the person's repo or settings.
- Chat sessions: no `notify::watch`, no split, no rotation relay, no autopilot, no Local provider, no image attach.
- Agent markdown is rendered as React elements only — no `innerHTML`/`dangerouslySetInnerHTML`; only `http(s)` links, opened with `@tauri-apps/plugin-opener`.
- Colour: amber (`--state-working`/`--accent`) only for "agent working"; `--state-waiting` (blue) for "waiting for you" cards.
- Every new string in `packages/i18n/src/en.ts` and `pt-BR.ts` (pt-BR typed against en).
- Mode name: "Chat" in both languages.
- Preference key `agents.openAs`, values `"terminal" | "chat"`, unset = no row = `terminal`; carried with the person's account (`identity::prefs::MACHINE_CARRIED`).
- QA only in `pnpm tauri dev --config '{"identifier":"dev.jarvis.desktop.chatqa"}'`, in a scratch project with a **long** path (no `~1` 8.3 segments); never the real `jarvis.db`; agent tests only in scratch repos.
- File patches via Write/Edit, not heredoc. Commit per task, message explains why, ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. No push.

## Review Focus

1. **The CLI asks something the driver does not know** (a new `control_request` subtype, an unknown Codex server request): it must get an error reply at once, or the agent hangs forever on a question nobody sees. → test in Task 3 and Task 4.
2. **The person sends while the agent is working, or double-clicks Send:** Claude must get both messages in order and `busy` must stay true until the last `result`; Codex must `turn/steer` into the active turn instead of starting a second one. → tests in Tasks 3/4.
3. **A permission card is answered after the process died or the request was already resolved** (stale card, app reload): the answer is refused with a code (`chat.requestGone`), never written to a closed pipe silently, and the card disappears. → test in Task 5.
4. **Agent output containing raw HTML, `javascript:` links or unterminated code fences:** shown as text; a fence left open by a streaming draft renders as a code block, not as a swallowed page. → tests in Task 7.
5. **`/model`-style transcript echoes and Codex command arrays** must not surface as "You" bubbles or empty activity rows. → tests in Task 1.
